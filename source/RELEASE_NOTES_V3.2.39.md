# MabiAuto V3.2.39 — 반복 누락 의심 원인 추적 및 시설별 병목 분석

## 반영 사항
- 기존 F9 다중가공 중간관리자의 **시설별 독립 진단**을 추가했습니다. 확인된 제법이 타 시설의 대기열 포화 때문에 보류된 사건, 제법 상태 불일치, CLI 작업의 실질적 정체, 가공 배치 결과 미확정 사건을 구분합니다.
- 같은 시설의 동일한 보류 사유를 계속 조회하는 것은 새로운 사건으로 세지 않습니다. 실제 보류 해제 후 다시 발생할 때만 재발로 집계하고, 사건 두 번 이상이면 원인 검토 대상으로 표시합니다.
- 시설별 직전 작업 수, 완료 슬롯 수 및 보류 지속시간을 기록합니다. 시계 역행 시 음수 대기시간을 계산하지 않습니다. 작업 ID와 실제 수령·누락은 증거 없이 확정하지 않습니다.
- F9 종료 로그에 시설별 병목 요약을 추가합니다. 오류 발생 시에는 기존 로컬 진단 JSON에 최대 8개 시설의 원인별 카운터를 함께 저장합니다. 원시 패킷, 오류 메시지, 화면 이미지, 계정·캐릭터 식별정보를 새로 저장하지 않습니다.
- 메모리 유지 대상 시설은 실행당 최대 16개이고, 모든 병목 기록은 이번 F9 실행에 한정됩니다. 과거 세션 간 재발률은 이번 버전에서 임의로 계산하지 않습니다.

## 기존 안전 규칙
- 병목 판별 자체는 화면 클릭, 등록·수령·제작·채집 재시도의 근거가 아닙니다. F9/F05 영속 장부, 원재료 부족 시 기존 재귀 해결, F10 정지, 중복 실행 차단, 0 정령의 날개 및 AI 수정 승인·롤백을 유지합니다.
- V3.2.38의 작업 검증 비율 및 V3.2.37의 CLI 읽기 복구율을 변경하지 않습니다. 시설 병목 횟수는 **확정된 생산품 누락 건수**가 아닙니다.

## 테스트 및 배포
- 같은 장애 반복 조회를 중복 집계하지 않는지, 실제 보류 해제 후 재발로 인식하는지, 완료된 옛 작업만 보고 병목을 해제하지 않는지, 시계 역행·시설 수 상한·진단 JSON 비공개성을 검증합니다.
- Windows PR CI 및 병합 후 main CI가 성공한 경우에만 정식 V3.2.39 자동업데이트 릴리스로 게시합니다.
- 실제 게임 장시간 운영 성과는 사용자 환경의 현장 검증이 필요합니다.
