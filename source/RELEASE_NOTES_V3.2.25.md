# MabiAuto V3.2.25 — 다중가공 식재료 시설 독립 진행 복구

## 실제 오류 및 원인

- 2026-10-18 제공 실행 로그: 금속·옷감 가공 시설은 각각 7/7로 채워졌고, 16:05:35부터 16:48:20까지 약 43분 동안 `[다중가공] 병렬 대기`만 반복되었습니다. 식재료 시설의 '밥' 신규 등록 기록은 없었습니다.
- V3.2.24는 최초 F9 시작 시 선택한 품목 중 하나라도 전역 `queue_full`이면, 다른 시설이 7/7인 동안 **빈 슬롯이 있는 모든 독립 시설**을 계속 건너뛰었습니다. 최초 CLI 상태가 지속적인 전역 대기 금지로 오용된 것이 원인입니다.

## 수정 내역

- **선택 시설별 독립 CLI 재확인**: 다른 시설이 7/7로 가득 차더라도 대상 식재료 시설이 접근 가능한 빈 슬롯을 가지고 있으면, 현재 선택 품목(예: 밥)의 제법을 새 CLI 조회로 다시 확인합니다.
- **가공 가능/부족재료 분기**: 제법 동일성(품목명·순번·생산량·시설)을 확인한 뒤, `Alterable=true` 또는 실제 `MissingIngredients`가 있는 경우에만 기존 재료/현장/등록 검증 경로로 넘깁니다. 실제 무료 가공 클릭은 하위 엔진이 라이브 CLI, 현장 UI, 무료 버튼, 등록 수 변화를 모두 재검증한 뒤에만 수행합니다.
- **불확실한 경우 차단 및 진단 개선**: 여전히 `Reason=queue_full`만 표시되고 부족재료 정보도 없으면 신규 등록을 시도하지 않습니다. `독립 시설 보류`와 그 이유를 기록하므로 무한 대기 시 원인 확인이 가능합니다. 제법 자체가 달라지거나 확인할 수 없으면 안전 정지합니다.
- **기존 안전 정책 유지**: 정령의 날개 0개, 기존 7/7 전체 완료 후 묶음 수령, 기존 작업/장부/중간재료 소비 보호, 다중가공 F10 안전 정지, 이전 버전 보관 및 롤백 기능은 변경하지 않았습니다.

## CI 및 테스트

- PR #233에서 2026-10-18 로그의 '두 시설 7/7·식재료 빈 슬롯' 상태를 재현했습니다.
- 라이브 CLI가 밥 제법을 가공 가능으로 확인한 경우에만 식재료 시설 처리 함수에 진입하는지 검사합니다.
- 여전히 `queue_full`이면 클릭을 금지하고 로그에 사유를 남기는지 검사합니다.
- 라이브 제법이 조회되지 않으면 안전 정지하는지 검사합니다.
- 최종 버전 변경을 포함한 Windows 생산 엔진·통합 스케줄러 CI와 병합 이후 `main` CI가 성공한 정확한 커밋에서만 Windows Lite ZIP, SHA256 및 Source ZIP을 발행합니다.

## 실게임 검증 범위 및 주의사항

- Windows CI는 실제 게임에서의 우물 채집, 밥 등록 및 수령 성공을 보장하지 않습니다.
- **중요:** 라이브 CLI가 다른 시설 때문에 계속 `queue_full`만 반환한다면, 새 버전은 무작정 클릭하지 않습니다. 이 경우 `독립 시설 보류` 로그와 당시 게임 화면으로 추가 원인을 확인해야 합니다.
- 현재 게임 진행 중에는 임의로 실행 파일을 교체하지 않습니다. 정상 종료 후 V3.2.25 업데이트를 적용하고 실행 파일 버전 `3.2.25.0`을 확인하세요.
- 새 F9 실행에서 식재료 시설의 `독립 시설 진행 승인` / `독립 시설 보류`, `밥` 등록 횟수 변화, 정령의 날개 0개를 확인하세요. 실패 시 오류 기록과 화면을 보존하세요.
