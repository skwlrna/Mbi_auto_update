# Mabi Auto V3.2.97 — F9 금속 가공 수령 현장 재사용 안전 검증

## 오류 근거와 수정 범위

2026-11-06 06:18:19 KST, V3.2.94 업로드 로그에서 금속 가공 기존 4건 완료 후 `ReuseCoordinatorConfirmedOnsite` 수령 지시를 받았습니다. 하지만 `CollectAsyncAtBoundary`는 지시 종류와 무관하게 `EnterFacilityAsync`부터 호출했고, 화면을 일반/전환 중으로 판단하여 9초 동안 K/I/Space를 인증하지 못하고 안전 정지했습니다. Space 수령 입력 전 오류입니다.

- `ReuseCoordinatorConfirmedOnsite` 수령은 일반 시설 진입/K 메뉴 경로보다 **우선** 새 화면에서 목표 시설명과 전체 시설 UI를 2프레임 연속 검증합니다.
- 이어서 새 입력 직전 프레임과 CLI 비이동·안전 활동 상태를 다시 검증하고, 일치할 때만 기존 수령 절차로 진행합니다.
- 전환 중/메뉴/필드/팝업 등 화면이 불명확하면 K/Esc/시설 이동/수령 Space를 **추측하여 입력하지 않고** 관찰 증거를 기록하고 중지합니다. 사용자의 현장 지시도 화면 증거를 대신할 수 없습니다.
- K/I, K/I/Space, 시설 패널, 목표 제목, 팝업, 허브 상태를 오류 진단로그에 추가했습니다.
- 기존 CLI 시설 전체 완료, 중복 수령 방지, 영속 장부, 정령의 날개 0 사용, Fresh 이동과 단일가공 경로는 유지합니다.

## 검증과 배포

회귀 테스트는 2프레임 성공/1프레임 미달/최종 화면 변경/이동 중/CLI 불명을 각각 검사합니다. 정식 자동 업데이트는 main SHA에 대한 Windows CI 성공, 출시용 안전 검증, Windows ZIP SHA256, 실행파일 버전, 백업 및 롤백 검증 후에만 이루어집니다.

**실제 게임에서 오류 재발 방지가 확인된 것은 아닙니다.** 원본 PNG는 이번 분석 환경에서 직접 판독하지 못했고, 정상 회복 성공 여부는 V3.2.97 적용 후 새 실행로그로 확인해야 합니다. 실행 중인 기존 배치는 강제 종료하지 않습니다.

## 2026-11-06 22:29:37 KST 중간재료 소유권·장부 불일치 추가 대응

V3.2.96에서 보고된 `중간재료 이어하기 소유권과 저장 장부가 일치하지 않습니다 · 새 등록 없이 정지`는 활성 자식 소유권의 재개 시 원래 저장된 작업 목표(`TargetQuantity`)를 현재 재고 기반의 남은 수량으로 재계산해 직접 비교하는 경로에서 발생할 수 있습니다. 22:29 원본 업로드 로그 및 디스크 장부는 아직 조회되지 않았으므로 실제 불일치 항목은 확정되지 않았습니다.

- 활성 중간재료 소유권이 있으면 기존 체크포인트의 원래 목표/작업 수를 복원합니다. 재고 증감은 관찰 정보만 남기며 목표를 재생성하지 않습니다.
- 원래 요청 기준 재고·요청 수량과 저장 세션의 기준 재고·목표 수량이 일관되는지, 제법/시설/캐릭터가 일치하는지 검증합니다. 일치하지 않거나 기록이 없으면 입력 없이 안전 정지합니다.
- 재고만으로 목표 수량이 충족되어 보여도 활성 중간재료 소유권이 남아 있다면 체크포인트를 삭제하거나 완료로 간주하지 않습니다. 기존 등록·수령 장부의 엄격한 검증을 계속 사용합니다.
- 오프라인 회귀로 재고 변화 중 목표 보존 및 저장 파일/캐릭터/제법/기준 재고 불일치 차단을 확인합니다. 실제 게임 검증은 별도로 필요합니다.
