# Mabi Auto V3.2.97 — F9 수령 현장 재사용 선검증 및 화면 인증 진단

## 실제 오류 근거 (2026-11-06 06:18:19 KST, V3.2.94)

금속 가공 기존 4건 전체 완료 직후 중간관리자가 `ReuseCoordinatorConfirmedOnsite`로 묶음 수령을 지시했습니다. `CollectAsyncAtBoundary`는 재사용 지시를 검사하기 전에 일반 `EnterFacilityAsync`로 진입하여 미분류 화면에서 K/I/Space 2프레임 인증을 9초간 시도했고, 모든 프레임이 False였으며 K 입력 없이 정지했습니다. CLI `get_items` / `get_my_info` / `get_altering_works`는 정상 연결이었습니다.

이 기록은 **수령 전에 일반 재진입이 우선되어 발생한 잘못된 화면 경로**를 증명합니다. 다만 첨부된 원본 스크린샷은 이 패치에서 판독하지 못했으므로 **실제 그 순간 어떤 화면이 열려 있었는지는 확정하지 않습니다**.

## 수정 사항 (PR #393)

- `ReuseCoordinatorConfirmedOnsite` 수령 경로는 일반 K/허브 진입 루틴보다 먼저 현재 화면의 **정확한 시설명 + 독립된 시설 패널 구조를 2프레임 연속** 확인합니다.
- 이동 중이 아님을 새로운 읽기 전용 CLI 확인으로 검사한 후에만 기존 안전 수령 경로에 넘깁니다.
- 재사용 증거가 없거나 확인창·허브·음식 메뉴 등 화면이 충돌하면 **K/ESC/이동/Space를 추측 입력하지 않고** 관리자 불일치 예외로 안전 종료합니다. 단순 실패 시 `FreshMoveRequired`로 몰래 전환하거나 수령을 재시도하지 않습니다.
- 최초 시설 진입, Fresh 이동, 일반 단일 가공, 기존 수령 장부·영속 완료 판단과 정령의 날개 0개 원칙은 그대로 유지합니다.
- 일반 K 진입의 9초 실패가 다시 발생하면 K, I, Space 각각의 인식 성공 여부와 팝업/메뉴 판정 내용을 기록합니다.
- 시설 시각 게이트 허용·거부 회귀 테스트, K 경로 순서 정적 테스트, 이전 버전 릴리스 정책 회귀를 추가합니다.

## 검증 및 배포

- **실제 게임에서 금속 모두 받기까지의 완전한 성공은 아직 검증되지 않았습니다.** 배포 후 새 자동 로그 및 수령 후 작업수 감소/인벤토리 장부를 확인해야 합니다.
- 정식 공개 배포는 동일 `main` SHA Windows CI, 실행 파일 스모크, 자동 업데이트 ZIP SHA256 검증, 롤백 스크립트 존재와 일회성 태그 검증 후에만 수행합니다.
- 설치 중인 버전을 강제로 종료하지 않습니다. 문제 발생 시 제공된 `ROLLBACK_PREVIOUS.cmd`로 이전 버전으로 돌아갈 수 있습니다.
