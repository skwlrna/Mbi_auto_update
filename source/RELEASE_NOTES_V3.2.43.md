# MabiAuto V3.2.43 개발 후보 — 시설별 효율 계측과 독립 시설 안전 우선순위

## 변경 사항
- F9 다중가공 중 시설별로 **CLI 대기열 관찰 주기, 즉시 처리 가능 주기, 재료 보류 주기, 실행 호출, 확인된 등록/품목 완료**를 각각 집계합니다.
- 현재 CLI 대기열에서 모든 작업이 완료된 시설을 우선 검토하고, 다음으로 빈 시설·첫 실행 빈칸 시설을 검토합니다. 실행 중이거나 재료 보류된 시설은 그대로 기다립니다.
- 같은 우선순위 시설은 이전 주기에 대기만 했던 횟수를 고려하되, 서로 독립된 **시설 간 순서만** 변경합니다.
- 로그에 시설별 계측 요약을 출력합니다. 계측은 **현재 F9 실행 메모리에서만** 유지되며, 재시작 시 작업/등록 증명이 되지 않습니다.
- 스케줄러 호출이 있었다는 사실만으로 진척을 적립하지 않습니다. 확인된 등록 또는 완료 품목만 검증 진척으로 별도 집계합니다.

## 안전 제한
- 같은 시설 내부의 사용자가 선택한 **제법 순서, 단일 작업 1칸 엔진, 7칸 상한 및 전체 완료 후 수령** 원칙은 유지합니다.
- CLI 읽기 전용 정보는 **실제 수령·등록·이동을 허가하지 않습니다**. 기존 현장권한, 캐릭터 일치, 영속 장부, 수령 검증, 불확실한 실행 정지 규칙을 그대로 통과해야만 입력이 수행됩니다.
- 재료 공급 경로가 불명확한 음식의 보류가 다른 시설에 의해 임의로 해제되지 않습니다. 정상 재고·제법을 다시 읽고 명시적 이어하기 조건을 지킵니다.
- 정령의 날개, 자동 구매, CLI 쓰기 명령, 의심스러운 재등록 기능을 추가하지 않았습니다.
- 한 시설의 완료된 작업이 *모두 수령 가능*하다는 뜻은 아닙니다. 실제 수령은 기존 F9 현장·장부 검증이 결정합니다.

## 검증
- 기존 기본값(우선순위 변경 비활성) 보존 및 F9에서만 명시적으로 활성화
- 완료 배치 우선, 준비된 빈 시설, 재료 보류 시설 배제
- 준비된 시설의 대기 누적 반영 및 동일 시설 내부 제법 순서 불변
- 재료 보류에도 독립 시설 진행 가능, F10 안전 중단
- 기존 N02 이어하기, F9 가공, Windows 빌드 및 UI 안전 회귀

## 릴리스 상태
V3.2.43은 V3.2.42 개발 브랜치에 종속된 초안입니다. 앱 버전은 아직 V3.2.41이며, 이 기능에 대한 별도 공개 Release·자동업데이트는 없습니다. V3.2.41 실제 게임 확인과 선행 브랜치 배포 승인이 완료되기 전에는 정식 배포하지 않습니다.
