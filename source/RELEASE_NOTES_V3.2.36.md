# MabiAuto V3.2.36 — 중간관리자 오류 패턴 및 복구 판단 정밀화

## 구현 범위
- 공통 생활스킬 중간관리자의 **오류 원인/처리 결정 정책**을 명시적으로 구분합니다. `transient_read`는 기존 300ms·최대 1회 읽기 전용 재조회만 허용합니다. `transient_read_exhausted`, `invalid_cli_data`, `state_conflict`, `unconfirmed_action`은 GUI 입력/등록/수령 재실행 대신 진단 및 안전 정지합니다. F10 취소는 재조회하지 않습니다.
- 재조회에 성공한 경우는 `transient_read_recovered / ContinueAfterVerifiedRead`로 명시하며, 단순 시간 경과나 과거 성공 이력만으로 복구 성공을 선언하지 않습니다.
- 가공·채집·제작 공통 읽기 오류, 제작/채집 결과 미확정, F9 배치 오류를 **제한된 메타데이터**(작업 단계, 내부 작업 태그, 원인 코드, 복구 판단, 반복 횟수)로 기록합니다. 세션당 서로 다른 패턴 최대 24개만 유지하고, 반복 로그는 1·3·10회 이후 50회 간격으로 제한합니다.
- F9 기존 로컬 오류 진단 스냅샷에 최근 복구 패턴 최대 16개, 오류 원인 코드 및 `gameValidated=false`를 기록합니다. 원문 예외 메시지, 게임 패킷, 계정/캐릭터 식별 정보, 화면 이미지 및 AI 실행 지시를 추가하지 않습니다.
- 기존 AI 오류 이력은 **사용자가 확인한 게임 내 해결/재발**을 구별하는 별도 안전 시스템으로 유지합니다. 오프라인 테스트 통과나 비슷한 과거 오류는 게임 입력 허가 근거가 아닙니다.

## 복구 안전 경계
- 기존 F9/F05 영속 배치·수령 장부, 중복 차단 펜스, 실제 재료 재고·화면 완료 증거, F10 정지, 시설/전투 정체 감시, 정령의 날개 0개 사용 정책, AI 변경 승인·롤백을 변경하지 않습니다.
- 부족 재료의 채집·제작이나 다른 시설 병행 재개는 **기존 별도 정책이 실시간 근거로 승인하는 경우에만** 진행됩니다. 이번 버전의 오류 패턴만으로 새 작업을 시작하지 않습니다.
- 자동 수정 코드 배포나 AI가 단독으로 행동을 결정하는 기능은 추가하지 않습니다.

## 테스트 및 배포
- 요청 단계별 일시 오류 1회 재조회, 오류별 안전 정지, F10 취소 우선, 실제 CLI 재조회 성공과 오류 반복 분리, 개인정보 비수집, 패턴 보관 상한, F9 로컬 진단 저장 검증.
- PR/메인 Windows CI 성공 후에만 릴리스 워크플로가 정식 Windows Lite 및 SHA256을 공개합니다.
- 현장 장시간 게임 성공률은 별도의 실제 플레이 검증이 필요합니다.
