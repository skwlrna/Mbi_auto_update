# MabiAuto V3.2.22 — AI 작업공간 한도 복구 및 안전 재분석

## 주요 수정

- **AI 자동수정 작업공간 한도 표시**: 격리 Git worktree 사용량과 기본 보관 한도 30개를 AI 오류 내역에서 확인하고, 한도 3개 전부터 경고합니다.
- **안전 정리(명시적 동의)**: 사용자가 직접 요청할 때 Git 등록 주체·종료 상태·원본 보고서·작업 폴더 변경 여부를 검사하고, 검증된 깨끗한 종료 worktree 1건만 ZIP 보관 및 SHA256 검증을 마친 후 Git을 통해 정리합니다. 강제 제거는 하지 않습니다.
- **기존 코드·증거 보존**: 수정 중이거나 수정 파일, 미추적 파일, GitHub PR이 있는 작업공간은 정리하지 않습니다. 원본 오류 보고서, 스크린샷, 분석 결과, Git 브랜치, 이전 릴리스 소스는 자동 삭제하지 않습니다. 보관 대상이 없다면 정리를 차단합니다.
- **보관 한도 오류 재분석**: `worktree_retention_limit_reached`로 차단된 오류는 공간 확보 후 사용자의 별도 승인 하에 한 번만 새 격리 작업공간에서 Codex 분석을 다시 시도합니다. 원래 차단 결과는 유지합니다.
- **오래된 Git 소스/스냅샷 인식**: 최신 릴리스 SHA로 생성 및 검증된 pinned source snapshot을 사전점검에서 다시 검증하고, 기존 저장소 소속 worktree는 소유권을 확인해 보호합니다.
- **운영 안전장치**: AI는 수정안을 운영 EXE에 자동 적용하거나 병합·배포하지 않습니다. 매크로 종료 시 자식 AI 감시도 종료됩니다.

## 실사용 오류 근거

- 2026-10-16 22:42:22 KST의 어비스 퇴장·HUD 복구 오류 `ec6b620be2bd72a2`가 작업 공간 보관 한도 `worktree_retention_limit_reached` 때문에 Codex 실행 전에 차단되었습니다.
- 이는 어비스 오류 코드 자체가 수정됐다는 의미가 아닙니다. 이번 업데이트는 분석 환경을 복구하고 다시 분석할 수 있도록 합니다.

## 검증 및 한계

- PR #224의 Windows 빌드, Python AI watcher 회귀 테스트, 어비스·가공 스케줄러 회귀 검사를 통과했습니다.
- CI 통과는 실제 사용자 PC의 이전 작업 폴더 정리, Codex 로그인, 게임 오류 해결을 보증하지 않습니다.
- CI가 통과한 최신 `main`의 정확한 SHA에서만 Windows Lite + SHA256 + Source ZIP을 발행하며, 운영 중 게임 프로그램은 원격으로 강제 종료하거나 교체하지 않습니다.

## 업데이트 후 사용 순서

1. V3.2.22 배포 파일 또는 자동 업데이트를 설치하고 EXE 버전 `3.2.22.0` 및 패키지 `BUILD_COMMIT.txt`를 확인합니다.
2. `AI 오류 관리 → 오류 시간별 내역`에서 작업공간 사용량과 안전 정리 후보를 확인합니다.
3. `작업공간 안전 정리`에서 **본인이 승인한** 완료 작업 폴더 한 건만 ZIP 백업·검증 후 정리합니다. 변경된 수정안은 보존합니다.
4. 공간이 확보되면 22:42 어비스 오류를 선택하여 `공간 한도 재분석`을 눌러 별도 1회 Codex 분석을 요청합니다.
5. Codex가 수정 파일·회귀 테스트·검토 기록을 남기는지 확인합니다. 수정안이 생성되더라도 실게임 해결과 자동 적용은 별도 검증이 필요합니다.
