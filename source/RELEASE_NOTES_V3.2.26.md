# Mabi Auto V3.2.26 — 가죽 원재료 소진 시 기존 완료 작업 수령 복구

## 실게임 오류 (2026-10-18 17:55:24 KST)

V3.2.25 다중가공 실행 중 가죽 가공 시설의 기존 작업 6/7건이 모두 완료되었지만 수령하지 못했습니다. `가죽+`는 원재료 소진으로 신규 가공 금지 상태였고, 7번째 슬롯을 채울 수 없는데도 첫 F9 빈 슬롯 채우기 조건이 우선 적용되어 수령을 보류했습니다. 그 결과 동일한 대기열 상태가 495초간 유지됐고 120초 시설별 정체 감시가 전체 배치를 안전 정지했습니다.

같은 로그에서 **밥 가공은 기존 1건 + 신규 6건, 식재료 시설 7/7까지 등록**되어 V3.2.25 식재료 등록 개선이 실제 작동한 사실을 확인했습니다. 밥 목표 100개 완성 여부를 뜻하지는 않습니다.

## 수정

- `RawMaterialExhausted`가 이미 확인·저장된 품목에는 **초기 빈 슬롯 우선 채우기 예외를 적용하지 않습니다**.
- 진행 중인 작업이 하나라도 있으면 기존처럼 **모두 받기를 금지하고** 대기합니다.
- 해당 시설의 작업이 **전부 완료된 경우에만** 중간관리자의 기존 이동·화면·CLI·저장소 사전 확인을 거쳐 묶음 수령합니다.
- 수령 후 CLI 시설 작업 0건 및 영구 수령 장부를 확인한 뒤 `RawMaterialExhausted` 품목만 목표 미달로 종료하고, 나머지 시설은 기존 정책대로 계속합니다.
- 새 가죽 작업 등록이나 원재료 자동 채집, 정령의 날개 사용, 불확실한 화면에서 수령/Space 재시도는 추가하지 않았습니다.

## 회귀 테스트

- 현장 로그의 **가죽 6/7, 전부 완료, 원재료 소진 기록**을 사용해 실제 `AlteringAutomation.RunBatchAsync`와 시설 장부를 검증합니다.
- 정확히 한 번 수령, 6건 수령 영구 기록, 등록 0회, 날개 사용 0개, 목표 미달 정상 종료 후 재호출 시 무동작을 확인합니다.
- 6건 중 일부만 완료된 경우에는 수령 0회, 등록 0회로 안전하게 보류되는지 검증합니다.
- 생산 엔진 및 통합 스케줄러 Windows CI를 모두 통과한 커밋을 `main`에 병합한 후, 정확한 `main` CI 승인을 받은 경우에만 새 버전 Windows Lite ZIP / SHA256 / Source ZIP을 생성·공개합니다.

## 적용 및 주의

진행 중인 게임/매크로를 강제 종료하거나 기존 완료 작업을 임의로 수령하지 마세요. V3.2.26을 적용한 다음에는 중단된 F9 배치의 **검증된 이어하기** 기능을 사용하고, 같은 목표의 새 배치를 중복 생성하지 않도록 합니다. 계정·캐릭터/기존 장부/게임 작업 일치가 확인되지 않으면 프로그램은 안전 정지합니다.

CI 통과는 게임 현장 수령 성공을 증명하지 않습니다. 실제 게임에서 수령 후 CLI 작업 0건, 가죽 품목 목표 미달 종료 및 나머지 시설의 정상 진행을 확인해야 합니다.
