# MabiAuto V3.2.24 — 다중가공 밥 재료 선행채집 개선

## 수정 내역

- **F9 시작 시 전체 선택 품목 재료 점검**: 목재/금속/가죽/옷감/식재료 시설의 순번과 상관없이 현재 CLI 제법의 확인된 부족 재료를 먼저 계획합니다. 기존 가공 대기열의 수령 또는 추가 등록은 이 선행채집 단계에서 수행하지 않습니다.
- **밥 100개 물이 든 병 부족 대응**: 1회 가공에 2병, 34회 가공이 필요한 제법인 경우 보유량 0개를 확인한 상태에서 채집 계획이 물 68병을 요구하도록 수정했습니다. 실제 채집 가능 여부, 수량, 가방 상태, 안전한 필드 복귀는 기존 실행 직전 검사로 검증합니다.
- **전역 `queue_full` 정보 손실 복원**: 다른 시설에 7/7칸 가공 작업이 있어 CLI가 선택한 식재료 제법의 `not_enough_ingredient` 대신 `queue_full`을 표시해도, UI에서 사용자가 직접 선택했던 동일 제법·시설·순번·생산량·목표량의 부족 재료 증거가 확인되면 선행채집 계획에 포함할 수 있습니다. 불확실한 데이터로 채집을 시작하지 않습니다.
- **재료 중복 소비 방지 유지**: 실행 직전 CLI 보유량 재조회, 기존 배치 수령/가공 등록 증거, 위치 확인, 비용 0개 원칙 및 F10 취소 경로를 유지합니다.
- **이어하기 보호**: 기존 F9 이어하기 배치는 새로운 선행채집 단계를 자동 적용하지 않으며 기존 저장 장부와 검증 동작을 유지합니다.

## 실제 오류 근거

- 2026-10-17 16:27 KST V3.2.23 다중가공: `밥 100개` 작업은 선택됐지만 `물이 든 병 0/2`, 등록 `0/34` 상태였고 목재 시설의 K 재진입 HUD 확인 실패로 전체 중단되었습니다.
- 2026-10-17 20:33 KST 다중가공: 나무 진액 채집 중 `Dialogue=True` 상태로 안전 정지. 그 실행에서 밥의 물 채집이 성공했다는 증거는 없습니다.

## 테스트 및 배포 조건

- PR #230의 기존 생산 엔진·가공·채집·통합 스케줄러 Windows CI 통과 후, 버전 변경을 포함한 새 커밋도 `main`의 전체 CI가 통과해야 공개합니다.
- 회귀 테스트는 34회 × 2병 = 최소 68병, 재료 부족 마스킹 복원, 기존 식재료 작업 보존, 잘못된 캐시 거부, 채집 후 밥 등록 가능 여부를 검증합니다.
- CI는 실제 게임에서 우물 채집/밥 제작의 성공을 증명하지 않습니다. 현장 검증 전까지 HUD, 이동, 채집 도구, 가방 부족 및 불확실한 화면은 기존처럼 안전 정지합니다.
- Windows Lite, SHA256, Source ZIP을 같은 CI 승인 커밋에서 생성합니다. 이전 버전은 기존 롤백 경로로 보관됩니다.

## 설치 후 확인

1. 프로그램을 정상 종료하고 V3.2.24 자동 업데이트 또는 Windows Lite ZIP을 적용해 파일 버전 `3.2.24.0`을 확인합니다.
2. 다중가공 목록에 밥을 선택하고 `물이 든 병` 수량 부족 상태에서 F9를 실행하면 `[다중가공] F9 전체 품목 선행채집 점검`과 `[다중 채집] 시작 · 물이 든 병` 기록을 확인합니다.
3. 우물 무료 채집의 재고 증가와 식재료 작업 등록 `0/34 → 1/34` 및 실제 수령 증가를 게임/CLI와 대조합니다.
4. 안전 정지 시 임의 반복 클릭하지 말고 저장된 로그/스크린샷을 이용해 오류를 분석합니다.
