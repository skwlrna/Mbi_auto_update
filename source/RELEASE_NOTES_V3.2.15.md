# MabiAuto V3.2.15 — 기존 가공 7칸 대기열 수령·재등록 복구

2026년 10월 15일 18:57 KST에 전송된 V3.2.14 실사용 오류 로그를 반영한 수정 버전입니다. CLI 연결과 `get_alterable_items`는 성공했지만 91개 제법 모두 `Alterable=false`로 반환됐고, `상급 목재`·`합금강괴`는 `Reason=queue_full`, `MissingIngredients=[]`였습니다. V3.2.14 F9 사전 검사가 이를 제법 자체의 가공 불가능 조건으로 오판하여 기존 가공 대기열 수령 로직 진입 전에 중단됐습니다.

- **기존 동작 복구:** 선택 시설 중 CLI `get_altering_works`에서 실제 작업 **7/7칸**이 확인되면 `queue_full`을 제법 오류가 아닌 현재 대기열 점유 상태로 처리합니다. 기존 중간관리자의 **대기 → 전체 완료 검증 → 안전 수령 → 빈 슬롯 재등록** 흐름으로 넘깁니다.
- **다중 시설 안전 순서:** 하나의 선택 시설이 7/7칸이면 다른 선택 시설에 대한 새 등록을 먼저 시도하지 않고, 기존 가득 찬 배치가 해소된 뒤 다음 시설을 진행하도록 보류합니다.
- **모순 감지:** CLI가 `queue_full`이라고 보고하지만 선택 시설 어디에도 7/7칸 근거가 없다면 입력 없이 중단합니다. 슬롯 조회 실패, 생산 제법 식별 불가, 예상 수량/순번 변경 등도 계속 차단합니다.
- **진단:** `[CLI][가공 대기열] queue_full 재검증` 로그에 선택 시설별 현재 작업 수와 완료 건수를 기록합니다. CLI 원본 개인정보는 저장하지 않습니다.
- **기존 안전정책 유지:** 기존 작업 삭제 금지, 수령 확정/작업 장부 검증, 시설 소유권 및 정체 감시, 재료 부족 처리, 정령의 날개 0개 사용 정책을 유지합니다.

## 테스트 및 적용

PR #207의 Windows 전체 CI 및 스케줄러 테스트를 통과한 수정 코드에 기반합니다. 새 자동업데이트 버전의 Windows CI와 최신 `main` 검증이 통과한 경우에만 별도 V3.2.15 공개 릴리스가 생성됩니다. 기존 V3.2.14 등 과거 릴리스는 덮어쓰지 않습니다.

실제 게임에 설치한 뒤 **기존 가공 대기열이 7칸 가득 찬 상태에서 스케줄러 시작 → 전체 완료 대기 → 수령 → 다음 가공 등록**을 확인해 주세요. 자동 테스트는 게임 클라이언트와 직접 연동한 실사용 성공을 보증하지 않습니다. 슬롯 수와 CLI 사유가 불일치한다면 새 로그를 통해 추가 진단이 필요합니다.
