# V3.2.41 후보 변경: 다중가공 음식 재료 보류의 영속 복구

## 범위
- 기존 V3.2.40의 식재료 자동 확보 경로 미확인/도구 부족/퀘스트 한정 재료는 **그 음식만 보류**하고 다른 시설 작업은 지속합니다.
- 재료 보류 품목 키·재료·부족 증거·최초 보류 시각·마지막 확인 시각·재검사 횟수를 기존 `batch.json` 원자 장부에 같이 저장합니다.
- F10·프로세스 종료 뒤 **사용자가 명시적으로 '최근 작업 이어하기'를 선택**하면 기존 캐릭터/대기열/수령/등록 증명 절차 이후 보류 품목을 복원합니다.
- 복원된 보류는 즉시 **새로운 읽기 전용 CLI 재고·제법 재확인**을 거치며, 시간이 지났다는 이유만으로 재등록하지 않습니다.
- 보류 갱신과 해제는 기존 장부 원자 저장 성공 이후에만 인메모리 스케줄러에 반영됩니다.
- 해당 식재료 시설의 다음 제법은 이전 보류 품목이 실제로 끝나기 전까지 진행하지 않습니다.

## 안전 제약
- 자동 구매 없음, 정령의 날개 사용 없음, CLI 쓰기 명령 추가 없음.
- 화면상의 기존 현장 확인/등록/수령 가드 완화 없음.
- 미확정 입력, 손상된 장부, 잘못된 캐릭터/시설, 원자 저장 실패는 자동 재실행하지 않고 정지합니다.
- 앱이 다시 시작되었다는 사실만으로 **자동 게임 입력/무인 재실행하지 않습니다**. 기존 명시적 이어하기 및 동일 캐릭터 확인 정책을 유지합니다.
- 완료된 품목의 결과 수량은 추정하거나 다시 적립하지 않습니다. 모든 입력 권한은 기존 검증된 장부에만 있습니다.

## 검증
- `tests/n02-resume`: 저장→종료→다시 열기, 갱신/해제, 손상된 키 거부, 저장 실패 시 원본 보호.
- `tests/altering`: 복원 보류를 신규 재고 확인 전에는 처리하지 않음, 다른 시설 진행, 쓰기 실패의 무입력 안전 정지.
- V3.2.41 버전 상수/EXE 버전은 **시험용 빌드 식별용**으로 먼저 상향하되, PR 빌드 결과는 공개 GitHub Release가 아니며 설치된 V3.2.40 사용자에게 자동 업데이트되지 않습니다.
- 시험용 ZIP은 `V3.2.41 Isolated Windows Candidate` GitHub Actions에서 생성합니다. 공식 설치 폴더가 아닌 **별도 폴더**에서 검증해야 합니다.
- `release-v3241-auto-update.yml`은 **수동 workflow_dispatch 승인** 이후에만 실행됩니다. 실행 전 현재 main의 동일 커밋에 대한 생산 CI 성공을 다시 확인합니다.
- 공개 릴리스가 승인·생성되면 기존 버전 검사로 자동업데이트가 가능하며, 기존 `.previous_version` 백업 및 `ROLLBACK_PREVIOUS.cmd` 경로는 유지합니다.

## 실제 게임 검증 체크리스트 (아직 미실행)
1. 시험용 빌드를 별도 폴더에서 실행하고 CLI 캐릭터 정보가 의도한 캐릭터임을 확인합니다.
2. F9 음식 가공의 구할 수 없는/미확인 재료를 부족하게 만들어 **음식 시설만 보류**되며 다른 시설이 계속되는지 관찰합니다.
3. 기존 실행에서 새 음식 등록/수령이 이루어지지 않았음을 로그 및 게임 대기열로 확인하고 F10으로 중지합니다.
4. 프로그램을 닫았다 다시 켜도 **자동 시작하지 않는지** 확인한 뒤, 같은 캐릭터 확인과 명시적인 '최근 작업 이어하기'만 실행합니다.
5. 기존 재료가 부족한 동안 등록 버튼을 누르지 않는지, 실제 재고 확보 뒤 **새 CLI 재확인** 후에만 해당 음식이 진행되는지 확인합니다.
6. 잘못된 캐릭터/손상된 장부/미확정 수령 상황에서는 자동 재등록 없이 정지하는지 테스트 환경에서 점검합니다.
7. 문제가 있으면 시험용 실행을 중지하고 정식 설치 폴더는 변경하지 않습니다. 공식 릴리스 후 오류가 발생하면 기존 백업을 통한 롤백을 사용합니다.

**주의:** GitHub Actions 성공은 실제 게임 검증이 아닙니다. 본 문서의 체크리스트를 수행한 사실을 확인하기 전에는 정식 배포 승인을 진행하지 않습니다.
