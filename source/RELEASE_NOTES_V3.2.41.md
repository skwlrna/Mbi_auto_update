# V3.2.41 후보 변경: 다중가공 음식 재료 보류의 영속 복구

## 범위
- 기존 V3.2.40의 식재료 자동 확보 경로 미확인/도구 부족/퀘스트 한정 재료는 **그 음식만 보류**하고 다른 시설 작업은 지속합니다.
- 재료 보류 품목 키·재료·부족 증거·최초 보류 시각·마지막 확인 시각·재검사 횟수를 기존 `batch.json` 원자 장부에 같이 저장합니다.
- F10·프로세스 종료 뒤 **사용자가 명시적으로 '최근 작업 이어하기'를 선택**하면 기존 캐릭터/대기열/수령/등록 증명 절차 이후 보류 품목을 복원합니다.
- 복원된 보류는 즉시 **새로운 읽기 전용 CLI 재고·제법 재확인**을 거치며, 시간이 지났다는 이유만으로 재등록하지 않습니다.
- 보류 갱신과 해제는 기존 장부 원자 저장 성공 이후에만 인메모리 스케줄러에 반영됩니다.
- 해당 식재료 시설의 다음 제법은 이전 보류 품목이 실제로 끝나기 전까지 진행하지 않습니다.

## 안전 제약
- 자동 구매 없음, 정령의 날개 사용 없음, CLI 쓰기 명령 추가 없음.
- 화면상의 기존 현장 확인/등록/수령 가드 완화 없음.
- 미확정 입력, 손상된 장부, 잘못된 캐릭터/시설, 원자 저장 실패는 자동 재실행하지 않고 정지합니다.
- 앱이 다시 시작되었다는 사실만으로 **자동 게임 입력/무인 재실행하지 않습니다**. 기존 명시적 이어하기 및 동일 캐릭터 확인 정책을 유지합니다.
- 완료된 품목의 결과 수량은 추정하거나 다시 적립하지 않습니다. 모든 입력 권한은 기존 검증된 장부에만 있습니다.

## 검증
- `tests/n02-resume`: 저장→종료→다시 열기, 갱신/해제, 손상된 키 거부, 저장 실패 시 원본 보호.
- `tests/altering`: 복원 보류를 신규 재고 확인 전에는 처리하지 않음, 다른 시설 진행, 쓰기 실패의 무입력 안전 정지.
- Windows CI 및 실게임 확인 후에만 버전 상향·정식 자동업데이트 배포를 별도로 검토합니다.
