# MabiAuto V3.1.69 — F9 설비 이동 확인 후 안전 대기 및 이동 HUD 구분

## 실제 오류: V3.1.68 (2026-10-09 20:03:54)
- 목재 가공 '설비로 이동' → 근처 시설 없음 확인창 → **Space 1회 실제 성공**.
- 게임에서 말 타고 자동이동 시작, CLI '이동 중' 전환.
- 기존 광범위 초록색 검사에서 이동 정지 버튼과 스킬 HUD를 '팝업 잔존'으로 오인하여 재확인 단계에서 관리자 CLI 차단 오류 발생.

## 수정 내용: F9 중간관리자 전용
1. 첫 확인 Space 전송 후와 그다음 반복의 **팝업 판단보다 먼저** CLI 활동을 재조회합니다. 이동 중이면 출발을 확정하고 추가 Space 없이 도착 확인으로 넘어갑니다.
2. CLI 활동 조회 불명인 경우 두 번째 Space를 금지하고 상태를 계속 재조회합니다. 강제로 이동 완료를 승인하지 않습니다.
3. 확인 팝업 감지는 F9에서 실제 800x1000 화면의 **슬레이트색 중앙 모달 패널**과 **오른쪽 넓은 초록색 확인 버튼**을 동시에 요구합니다. 초록색 원형 이동 STOP 버튼·스킬 HUD만으로는 팝업을 승인하지 않습니다.
4. V3.1.47의 OCR 비필수 첫 확인, 이중 CLI 유휴 확인, 첫 클릭 연계, 최대 2회 확인, 실제 출발·도착 검증(7프레임/3초 및 별도 최종 확인)은 유지합니다.
5. 자동 단일가공의 기존 팝업 로직, 수령 완료창, 좌표 및 키보드 입력 방식은 변경하지 않습니다.

## 회귀 테스트
- 실제 19:35 모달과 20:03 탑승 STOP/스킬 HUD를 재현한 800x1000 이미지로 정탐/오탐 구분.
- 순수 초록 버튼/모달만 있음/빈 화면은 거부.
- 컴파일된 F9 이동 메서드가 새 모달 검출기와 Space 후 CLI 확인을 호출하는지 L2 검사.
- Windows CI·EXE 기동 점검 후 V3.1.69 출시. 실제 게임 첫 검증은 소량으로 수행할 것.

## 알려진 안전 우선 동작
- CLI 비이동 여부가 불확실하거나 실제 팝업이 재검증되지 않으면 두 번째 Space는 보내지 않습니다.
- 키 입력 시점과 CLI 갱신 간 경쟁이 완전히 불가능한 것은 아니므로, 게임 내 실측 확인이 필요합니다.
