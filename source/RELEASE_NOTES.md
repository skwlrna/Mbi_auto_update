# MabiAuto V3.1.89 — 시작 버튼/F9 무반응 개선 (UI 입력·오류 표시)

## 수정
- **제작·가공·스케줄러 화면의 하단 공통 시작 버튼**을 더 이상 숨기지 않습니다. 페이지 내부 시작 버튼과 F9도 같은 공통 실행 경로를 사용합니다.
- 사용자가 시작 버튼 또는 F9를 누르면 현재 모드, 작업 준비/실행 상태를 먼저 일반 로그에 기록하고 화면에 시작 요청을 표시합니다.
- 스케줄러에서 가공 품목을 선택하지 않았거나 작업 설정이 잘못되었을 때는 숨겨진 상태값만 바꾸지 않고 **스케줄러 페이지의 실행 안내 영역에 구체적인 거부 사유를 지속 표시**합니다. 정기 UI 리프레시가 사유를 지우지 않습니다.
- 실행 준비 도중 발생한 비동기 Task 오류도 관찰하고 화면 상태와 로그에 기록합니다. 이전에는 시작 함수가 반환한 실패 Task를 기다리지 않아 **F9나 버튼이 먹통처럼 보일 수 있었습니다.**
- F9 단축키를 운영체제에 등록하지 못한 경우에도 일반 로그에 남깁니다.
- WinForms 실화면 자동 테스트에서 하단 시작 버튼 가시성·실제 클릭 전달·F9 경로·입력 거부 사유·비동기 오류 표시·기존 가공 작업 미실행 보호를 확인했습니다.

## 테스트 주의
- **실사용 PC에서 발생한 먹통의 근본 원인이 이 결함들만으로 설명되는지는 아직 최종 확인되지 않았습니다.** 실행 후 이상이 지속되면 현재 화면, `app.log` 및 설치 폴더의 `ui-crash.log`를 확인해 주세요.
- 제작/가공/어비스의 기존 입력, CLI, F10 안전정지, 장부/감시 및 이전 버전 롤백 동작을 유지합니다.
- **전체 UI 디자인 전면 개편은 이번 긴급 수정에 포함되지 않았습니다.** 화면 구성 개선과는 별도로 처리합니다.

# MabiAuto V3.1.88 — 가공 병행 어비스 진입 시 이미 열린 메뉴 인식 실패 수정

## 현장 오류 근거
- 2026-10-12 V3.1.87 다중가공 로그: 09:55:59에 목재 가공 대기 중 어비스에 입력권을 넘겼으나, 실제 게임 화면에는 **우측 메뉴와 어비스 항목이 열려 있었음**. 기존 1단계는 닫힌 메뉴의 ESC 버튼 이미지만 90초 기다려 `abyss_menu found=0 score=0.435`로 실패.
- 이후 전투용 660초 복구를 세 번 잘못 시도해 10:30:36 스케줄러가 안전정지함.

## 수정
- 어비스 1단계에서 현재 우측 메뉴가 이미 열려 있는지 먼저 검사하고 **어비스 항목의 연속 2프레임 인식 시 ESC 메뉴 클릭을 생략**합니다.
- 아이콘 템플릿이 일치하지 않으면 해당 메뉴 셀의 정확한 '어비스' 문자와 별도 '길드' 항목을 교차 확인하는 OCR 경로를 사용합니다. 임의 클릭을 하지 않고 같은 메뉴 셀의 2프레임 확인 후 어비스 선택 화면까지 검증합니다.
- 어비스 진입 1~4단계의 자동복구를 전투/클리어용 660초 복구와 분리하고, 8초 안에 알려진 메뉴/던전 선택 화면이 확인되지 않으면 안전 실패로 처리합니다.
- 단일 라운드 병행 어비스에서 자동복구가 성공했을 때 실제로 해당 단계부터 계속 진행할 수 있도록 한도를 둔 재개 처리를 추가했습니다. 실제 던전 밖 HUD 검증 전에는 절대로 가공을 재개하지 않습니다.
- Windows 통합 스케줄러 테스트에 열린 메뉴 2프레임, 아이콘 좌표·OCR 문맥, 재개 한도, 기존 F10·가공 입력권 검사 등이 포함됩니다.

## 주의
- **정식 GUI 디자인 개편은 이번 수정 범위에 포함되지 않았습니다.** V3.1.87 UI 구성 그대로 어비스 메뉴 진입 결함만 수정합니다.
- 테스트는 Windows CI로 확인합니다. 실제 게임 클라이언트에서 메뉴 OCR 및 선택 화면 전환은 추가 현장 확인이 필요합니다. 오류 시 F10으로 중단하고 화면·로그를 확인해 주세요.
- 기존 업데이트 호환 ZIP, SHA256 검증, 오류 시 안전정지, 이전 버전 롤백을 유지합니다.

# MabiAuto V3.1.87 — 통합 UI 및 제작·다중가공·어비스 스케줄러 정식 자동 업데이트

- **통합 스케줄러:** 제작 품목을 먼저 진행하고 다중가공 대기 중에 어비스를 실행합니다. 스케줄러 어비스 설정에서 출발 최소 대기 기준을 90·120·180·240·300초 중 선택할 수 있으며 기본값은 120초입니다.

## 어비스 안전성 개선
- 800×1000 클라이언트 기준 결과 화면의 왼쪽 **나가기 (165,930)**, 가운데 **다시 하기 (400,930)**를 버튼 화면·초록 배경 반복 검증 후 클릭. 클라이언트 크기 변화와 화면 비율 오류에서는 클릭하지 않습니다.
- **단독 어비스**는 결과 화면 확인 후 가운데 다시 하기; **가공과 병행하는 어비스**는 결과 화면 확인 후 왼쪽 나가기. 클릭 후 필드 HUD 또는 전투 복귀를 별도로 확인합니다.
- 어비스 **재접속·Smart Recovery·타임아웃 복구**가 함수 정상 종료처럼 반환되어도, 실제 던전 밖 HUD가 연속 3회 확인되지 않았다면 **가공 감독자에게 게임 입력권을 돌려주지 않습니다.** 복구 중 결과 화면을 만나도 병행 모드에서는 다시 하기 대신 나가기 절차를 사용합니다.
- F10 및 예약 중단, 정체 감시, 장부 영속화, 실패 시 안전정지 규칙을 유지합니다.

## 배포 및 테스트 주의
- Windows CI 전체 회귀 검사와 스케줄러 회귀 검사 후, **실제 main 커밋 SHA**에서 Windows Lite 패키지(프로그램 EXE, 감시 프로그램, 설정·이미지·Interception)를 빌드하고 EXE 실행 스모크 테스트·SHA256 검증 후에만 공개합니다.

1. 이미 시설/허브 판정을 우선 처리한 기존 흐름 뒤, **일반 필드 HUD 2프레임 확인 + 실제 팝업 부재**가 확인되면 더 이상 동일 프레임의 부정확한 '시설/허브 밝기 픽셀'로 K 전송을 건너뛰지 않음.
2. K키 직전 `RequireManagedIdleAsync`의 CLI 비이동·비채집 확인과 실제 팝업 판별, 2프레임 일반 필드 검증은 **그대로 유지**.
3. 실제 가공 허브/시설은 기존 선행 분기로 처리. K 메뉴 진입 후 구조/텍스트 확인·시설 고정 좌표·원재료 부족 처리·가공 수령·정령의 날개 0개 원칙은 변경하지 않음.

## 자동 검증과 한계
- 실제 컴파일된 `EnterFacilityAsync` 호출 경로에서 K 직전 고정 헤더/허브 후행 차단 호출이 제거됐으며, 모달·필드 HUD·CLI 게이트와 K 입력은 남았는지 L2 검사.
- 정상 필드 HUD와 오탐을 유발할 수 있는 밝은 시설 헤더 패턴이 동시에 나타나는 합성 프레임 검사, 기존 실제 팝업/빈 화면 차단 검사 유지.
- GitHub CI 통과는 **실게임 자동화 성공을 증명하지 않음**. 첫 사용은 적은 작업 수로 확인하고 오류 시 추가 입력 없이 정지해야 함.

# MabiAuto V3.1.72 — F9 중간관리자 CLI 우선 · K 메뉴 중복 OCR 축소

## 목표
- 다중가공 작업 개수, 완료 여부, 재료 수량, 자동이동 및 입력 가능 상태 판단은 계속 CLI를 권위 있는 기준으로 사용.
- 가공 UI의 **실제 입력 위치와 팝업 존재**는 화면의 확인된 구조로만 검사. CLI 정보만으로 특정 화면이 열렸다고 가정하지 않음.

## 수정 내용 (F9 K 메뉴 탐색 전용)
1. 현재 F9가 보이는 K 가공 메뉴의 세 개 독립적인 하단 글자 영역(빠른 제작/제작/연금술)을 화면 고정 구조로 검증. 800×1000 레이아웃과 기존 가공 허브/시설창 분리 조건 유지.
2. 160ms 간격으로 실제 화면 **2프레임**에서 같은 구조가 확인되면 기존 한국어 OCR 3회(초기 메뉴 탐색 + ClickLabel 두 번)를 생략하고 검증된 가공 탭 (360,948)에 1회 클릭.
3. 화면에는 실제 모달 패널/확인 버튼이 없어야 하며, 클릭 직전 중간관리자의 기존 `RequireManagedIdleAsync` CLI 비이동/비채집/비전투 검사를 통과해야 함.
4. 메뉴 구조가 불명확하면 고정 좌표로 누르지 않고 기존 bounded OCR 검사를 그대로 사용. F9 일반 필드 HUD가 먼저 확인되면 메뉴 글씨 OCR 없이 기존 안전한 K 진입 경로로 진행.
5. F9 K 진입 직후의 화면 대기 과정은 시설 화면·6카드 가공 허브·하단 메뉴의 **구조만** 확인하며 불필요한 반복 OCR을 하지 않음. 실제 품목/시설의 정확한 이름은 기존 OCR/검증 규칙 유지.
6. 일반 단일가공, 채집의 굵은 나무 OCR 2프레임, 완료품 수령, 설비 이동 Space, 원재료·중간재료 계산 및 저장 복원 로직은 변경하지 않음.

## 검증 및 제한
- 실컴파일된 F9 메뉴 경로에서 CLI 유휴·팝업 차단·화면 2회 구조 인식 후에만 고정 탭 클릭하는 L2 검사.
- 필드 풀밭 / 허브 / 확인 팝업 / 클라이언트 크기 불일치에 대한 합성 화면 회귀 테스트.
- 메뉴 화면 레이아웃은 기존 캡처 기반이라 게임 UI가 달라지면 OCR fallback 또는 안전 정지가 발생할 수 있음. 새 버전 적용 후 적은 작업 수로 실게임 테스트 필요.
