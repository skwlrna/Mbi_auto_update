# MabiAuto V3.1.66 — 수령 직전 반복 검사 간소화 및 CLI 불변 시 한 번만 파란 버튼 재시도

## 실제 2026-10-09 16:12 V3.1.65 오류
- 기존 목재 가공 7건 모두 100% 완료. (85,235) 설비 이동 클릭 후 버튼 영역 픽셀 변화 60%, 현장 도착 안정검증 통과.
- 파란 모두 받기 최초 2프레임 검사는 통과했고 수령 전 전체 작업 수 7건을 확인했지만, 기존 400ms 대기 이후의 중복된 2프레임 검사에서 안전 정지.
- 오류 화면에는 시설 제목과 파란 모두 받기 버튼, 완료된 7건이 그대로 보였습니다. 당시 어떤 개별 조건이 실패했는지는 로그가 없어 확정되지 않았습니다.

## 변경 사항
- 중간관리자 다중가공은 설비 도착 뒤 최신 현장+CLI 전체 완료+파란 버튼 검사를 1회 수행하고, 오래된 2프레임/400ms/2프레임 반복 검사는 생략합니다. (단일가공 Automatic의 기존 방식은 변경하지 않음)
- 매니저 수령 전용 RecoveryRequired 기록 저장 이후에는 **F02 최종 새 화면+전체 슬롯 완료 검증**과 F03 CLI 활동 검사를 유지합니다. 따라서 기록 I/O 중 UI/CLI가 변하면 Space 없이 중지합니다.
- 파란 모두 받기 버튼의 화면 인식 영역만 실제 버튼 위치에 맞게 (15,245,100,60)으로 보정. 고정 클릭 좌표, 기존 (85,235) 설비 이동과 수령 Space 방식은 변경하지 않았습니다.
- 첫 수령 Space 후 CLI 작업 수가 그대로이면, 이전의 수령 결과 확인 절차를 먼저 완전히 수행합니다. 실패한 경우에도 실제 작업 수가 최초 수와 **2회 연속 동일**, 전체 작업 완료, 실제 파란 버튼, 동일 현장, 현장 X, 팝업 없음, CLI 비이동인 경우에만 Space를 **딱 1회 추가**할 수 있습니다.
- 7→0 정상 수령, 7→6 부분 수령, 작업 수 확인 실패, 완료/이동 팝업, 파란 버튼 부재, 이동 중 또는 미확인, 이미 재시도한 경우 추가 수령 없이 RecoveryRequired로 안전 정지합니다.
- 두 번째 Space 후에는 기존 CLI 시설 전체 비움·수령 결과 확인을 반드시 통과해야 성공 처리합니다.

## 테스트
- 실제 컴파일된 가공 화면과 정책: 수령 가능 단일 검사, F02 저장 경계→새 화면 확인→Space, 재수령 클릭 최대 1회.
- 이전/이후 CLI 건수 동일(7→7)만 허용, 7→0/6/불명, 파란 버튼 없음, 모달, 이동, 중복 재시도 모두 차단.
- 실제 800×1000 화면의 파란 모두 받기 버튼 픽셀 인식 위치를 합성 프레임 테스트로 검증.
