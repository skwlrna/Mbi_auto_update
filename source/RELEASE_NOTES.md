# MabiAuto V3.1.57 — 중간관리자 복귀 · F9는 무조건 새 배치

## 배경
V3.1.56에서 2026-10-08 21:30:57 오류 `F05 미확정 소비 거래 · RecoveryRequired`가 발생했습니다. 과거에 중단한 V3.1.55/56의 `limited-fresh-test/batch.json`을 다시 열고 이어하기 때문에 새 테스트까지 차단됐습니다. 사용자가 **이전 가공 이어하기를 원하지 않으며 1캐릭터만 사용**한다는 운영 방침을 확정했습니다.

## 정책: 사용자 F9는 전부 중간관리자 소유 (PR #131)

- 사용자 F9의 **한 품목 또는 여러 품목 전체를 `MultiAlteringCoordinator`에 일괄 전달**합니다. 중간관리자가 시설별 7개 슬롯, 같은 시설의 라운드로빈 혼합, 작업 등록·완료·시설 단위 수령, 부족 재료 해결 순서를 통제합니다.
- F10은 현재 자동 입력을 중단합니다. F10 뒤나 재시작 뒤 이전 작업 계획을 **자동 복원하지 않습니다**. 사용자가 다시 선택하여 F9를 누르면 새로운 배치를 시작합니다.
- F9마다 `%LOCALAPPDATA%\MabiAuto\multi-altering\fresh-runs\f9-<고유ID>\batch.json`에 **새로운 N02/F05 장부**를 만들며 원본 `multi-altering\batch.json`, `limited-fresh-test\batch.json`, 기존 plan/재귀 기록은 삭제·변경하지 않습니다.
- 기존의 오류 발생 지점인 과거 `PreparedConsumption`을 새 실행에서 열지 않습니다. **과거 오류 기록은 그대로 보존하고 새로운 작업만 독립 실행**합니다.
- 새 F9는 선택한 시설 내 대기·완료 미수령 작업이 **0건**일 때만 새 등록을 허용합니다. 관련 없는 다른 시설 대기열은 유지합니다. 이전 작업이 남아 있으면 자동 수령·취소·재등록하지 않고 정지합니다.
- **현재 실행의 N02 완료 수량 장부, F05 소비 보정, 안전 수령 검증, 인터셉션 입력 취소, 근거리 즉시 설비 도착 검증을 유지**합니다.
- 구버전 프로그램과 동시 실행되지 않도록 기존 루트 배치 잠금을 공유합니다. 이전 기록 자체의 안전성 여부는 해결된 것이 아니며, 나중에 이어하려면 별도의 안전 검토가 필요합니다.

## 테스트 및 주의사항

- PR #131: Windows CI 29개 단계 모두 성공. N02 재현/안전 테스트에 과거 미확정 F05 존재 + 별도 새 F9 시작, 새 F9마다 다른 배치 생성, 선택 시설에 대기·완료 작업 있을 때 차단, 무관한 시설 작업 유지, 기존 경로가 있으면 안전 정지 항목을 추가했습니다.
- 자동가공 CI의 예전 '이어하기 목록을 항상 복원' 강제 검사를 사용자 의도에 따라 '신규 F9에서는 자동 복원 금지'로 바꿨습니다.
- 이는 모의 게임/파일 기반 Windows 검증입니다. **실게임 가공 성공을 보장하지 않습니다.** 처음에는 두 품목 10개 이하로 시험하고 설비 이동 → 가공 등록 → 자동 수령 결과를 확인해야 합니다.
- 프로그램을 V3.1.57로 업데이트 후 UI에서 품목을 다시 직접 선택하세요. 중단된 이전 작업이 **선택 시설**에 남아 있으면 실제 대기열이 0이 될 때까지 새 가공을 시작하지 않습니다.
- **절대** `batch.json`이나 `limited-fresh-test` 및 `fresh-runs` 폴더를 임의 삭제하거나 구버전과 동시에 실행하지 마세요.

Windows Lite ZIP, SHA256, Source ZIP을 CI 통과 이후 GitHub Release에 공개합니다. 기존 V3.1.56 롤백본은 유지합니다.
