# MabiAuto V3.1.56 — 1캐릭터 F10 이어하기, 대기열 범위, 근거리 설비 이동 보완

2026-10-08 V3.1.55 실게임 재현: 작업 2종(목재+ 10개 / 강철괴 10개)을 등록했고, 목재 설비로 이동 버튼 클릭 이후 매우 가까워 즉시 같은 시설 창이 다시 열렸습니다. 기존 F01 이동 전환 관측기가 이 빠른 이동을 놓쳐 약 86초 후 오류로 정지했습니다.

## 세 가지 수정 — PR #129

1. **1캐릭터용 복원**: CLI가 캐릭터 ID 없이 서버 정보만 줄 때에도 기존 `%LOCALAPPDATA%\MabiAuto\multi-altering\limited-fresh-test\batch.json`에 저장한 배치를 이어합니다. 완료 품목, 등록한 회수, 수령 기록은 그대로 유지합니다. 이전에 등록한 작업이 아닌 새 작업/계획 변경, 모호한 소비·수령 체크포인트는 자동 재등록하지 않습니다.
2. **대기열 범위**: 기존 전체 시설의 대기열이 0이어야 한다는 제한을 제거합니다. 신규 작업은 **선택한 시설에 기존 대기 작업이 없어야** 합니다. 선택하지 않은 시설의 작업은 취소하거나 수령하지 않습니다. 재개할 때에도 선택 시설의 실제 작업이 저장 장부와 일치해야 합니다.
3. **근거리 즉시 도착**: 클릭 전에 원격 **설비로 이동** 버튼을 긍정 확인하고, 클릭 후 같은 시설 화면·현장 닫기 X·원격 이동 버튼 없음·CLI 유휴·모달 없음이 동시에 성립하면 근거리 즉시 도착 후보로 인정합니다. 클릭 사실만으로 진행하지 않으며 7프레임/3초 안정성 및 1.2초 뒤 새 화면 재확인을 그대로 유지합니다. 설비 이동 클릭 반복은 하지 않습니다.

## 완료 기록 및 사용 주의

- 정식 배치의 과거 `multi-altering\batch.json`과 구형 `plan-*.json`은 원본 상태로 둡니다.
- 1캐릭터 전용 모드이므로 **다른 캐릭터로 게임 접속을 전환해 이 장부를 이어받으면 안 됩니다.** CLI는 ID를 제공하지 않아 같은 서버의 두 캐릭터를 기술적으로 구분할 수 없습니다.
- F10 뒤 동일한 시설/품목/제법/목표량으로 재시작하면 기존 제한적 저장 배치를 이어받습니다. **진행 중인 기존 배치의 목표 수량을 임의로 변경하지 마세요.**
- 모호하거나 손상된 기록, 새 외부 작업, 미확정 수령 등은 계속 안전 정지합니다. 기록 파일을 직접 삭제하지 마세요.
- 게임 내 품목 수량 10개처럼 소량으로 시험하고 실제 설비 이동/등록/수령 결과를 확인하세요.

## 검증 및 한계

- [PR #129](https://github.com/skwlrna/Mbi_auto_update/pull/129): Windows CI 29단계 통과.
- 추가 테스트: 완료 품목 포함 F10 재개, 동일 계획 충돌 방지, 선택 시설 외 대기열 허용, 등록되지 않은 타 작업 검출, F01 근거리 이동 이중 근거 및 거부 조건, 실제 컴파일된 화면 경로의 L2 검사.
- **CI는 가상 게임/화면 기반입니다. 실제 게임에서 모든 경로가 통과했다는 의미는 아닙니다.** V3.1.56 테스트 결과는 실행 로그로 확인해야 합니다.

정식 Windows 단일파일 실행용 ZIP, SHA256, 소스 ZIP을 CI-approved GitHub Release에 게시하며 V3.1.55 파일은 변경하지 않습니다.
