# V3.0.4

사용자가 제공한 실제 제작 검색창 화면을 기준으로 검색 입력칸 좌표와 목록 진입 타이밍을 수정한 패치입니다.

## 제작 검색
- 상단 검색 돋보기 좌표 `(30,118)`은 유지합니다.
- 검색창이 열린 뒤 아이템명 입력칸을 실제 화면 기준 `(400,862)`로 수정했습니다.
- 기존 `(400,425)`는 제작 목록 화면 중간을 클릭하던 잘못된 좌표였으므로 제거했습니다.
- 아이템/음식 카드 진입 후 검색 돋보기를 너무 빨리 누르지 않도록 제작 목록 안정화 대기를 `1200ms`로 늘렸습니다.
- 검색창 하단 팝업 감지 영역도 실제 화면 위치에 맞춰 하단 영역으로 보정했습니다.
- 검색창 열림/결과 전환 상태 검증과 추가 클릭 없이 정지하는 안전 규칙은 유지합니다.

## 유지
- 자동 가공과 자동 채집 실행 로직은 변경하지 않았습니다.
- Interception, Zero Wing 안전조건, 조회 전용 CLI, F10 정지, 업데이트 롤백은 그대로 유지합니다.

# V3.0.3

V3.0.2 실게임 제작 테스트에서 돋보기 클릭으로 검색창은 실제로 열렸지만 placeholder OCR이 실패해 프로그램이 검색창 미오픈으로 오판하고, 이후 OCR fallback이 다른 위치를 클릭하던 문제를 수정한 패치입니다.

## 제작 검색 상태 검증
- 제작 검색 돋보기 고정좌표 `(30,118)`은 실게임에서 정상 동작한 것으로 유지합니다.
- 검색창 열림 여부를 placeholder OCR로 판정하지 않고, 돋보기 클릭 전/후의 고정 검색창 ROI 화면 변화로 확인합니다.
- 검색창 화면 변화가 확인되지 않으면 다른 위치를 찾거나 클릭하지 않고 즉시 정지하며 진단 캡처를 남깁니다.
- 검색어 입력/Enter 이후 적용 화면도 적용 전/후 고정 ROI 화면 변화 또는 exact 결과 OCR로 확인합니다.
- 결과 화면 전환이 확인되지 않으면 첫 결과를 클릭하지 않습니다.
- 첫 결과 클릭 후 제작 상세 화면이 확인되지 않으면 Escape/OCR fallback 등 추가 클릭 없이 즉시 정지합니다.
- 제작 검색에서 `전체` OCR을 기준으로 돋보기를 다시 찾고 누르던 fallback 경로를 제거했습니다.

## 유지
- 자동 가공과 자동 채집 실행 로직은 변경하지 않았습니다.
- Interception, Zero Wing 안전조건, 조회 전용 CLI, F10 정지, 업데이트 롤백은 그대로 유지합니다.
- 동일한 OCR fallback 재발을 막는 V3 생산 회귀검사를 추가했습니다.

# V3.0.0

V2 계열에서 단계별 화면 인식 보정을 반복하던 생산 자동화를 **공통 상태 머신 + fresh-frame 화면 제어 엔진**으로 다시 구성한 메이저 업데이트입니다. 낚시·던전·어비스·업데이터·CLI 조회·Interception·F10·오류전송은 기존 구조를 유지하고, 제작/자동가공/자동채집의 화면 이동과 입력 판단을 재구축했습니다.

## 공통 생산 엔진
- 제작·자동가공·자동채집이 공통 `ProductionUiRuntime`을 사용합니다.
- 오래된 OCR 캡처와 현재 **전체 800×1000 화면의 픽셀 변화율을 비교하는 방식은 생산 화면에서 제거**했습니다.
- OCR 클릭은 대상 ROI를 두 프레임에서 확인하고, 입력 직전 새 캡처에서 **같은 대상 ROI만 다시 읽은 위치**를 사용합니다.
- 필드의 캐릭터·펫·불꽃·채팅처럼 정상적으로 움직이는 요소 때문에 메뉴 단축키나 고정 UI 이동이 중단되지 않도록 했습니다.
- `ProductionStageMachine`으로 `허브 → 분류 → 검색 → 상세 → 퀘스트/재료 → 이동 → 처리 → 재고검증 → 완료` 단계를 명시적으로 기록합니다.
- 잘못된 숨은 단계 점프는 중단하며, 화면 복구는 검증된 허브 재진입으로만 수행합니다.

## 공통 검색
- 게임 내 제작품·아이템·재료 검색을 `ProductionSearchFlow` 하나로 통합했습니다.
- 검색 순서는 항상 `검색창 → 이름 입력 → Enter → 적용하기 → exact 결과`입니다.
- Enter 없이 Space나 적용을 먼저 누르는 검색 경로를 사용하지 않습니다.
- 제작 목록과 가방 보조 경로가 동일한 검색 규칙을 사용합니다.

## 제작
- 음식/아이템 공통 엔진, CLI `get_craftable_items` 목록, 최대 10회 배치 퀘스트를 유지합니다.
- 제작 허브의 음식/아이템 카드는 제작 화면을 확인한 뒤 검증된 800×1000 카드 위치를 보조 신호로 사용할 수 있습니다.
- 퀘스트 제목, 부족 재료 행, 추천 획득처, 제작대 복귀 단계는 저장된 과거 좌표를 바로 누르지 않고 새 프레임에서 재확인합니다.
- 직접 재료는 `제작 퀘스트 → 구하는 방법 → 추천 획득처`를 사용하고, 목표 수량 이상이면 완료로 처리합니다.
- 중간 가공품은 기존 자동가공 계산/재귀 해결기로 연결합니다.
- 제작 완료 화면은 목표 품목과 완료 표시를 다시 확인한 뒤 Space를 누르고, 실제 CLI 재고 증가량으로 배치 성공을 확정합니다.

## 자동 채집
- 단독 채집과 자동가공 원재료 확보는 **생활 스킬 100회 채집**을 우선합니다.
- 100회가 끝날 때마다 실제 CLI 재고 증가량을 확인하며, 100회=100개라고 가정하지 않습니다.
- 확인된 일상 채집/나무 베기/광석 캐기/약초 채집/양털 깎기/추수/호미질 매핑만 단독·대량채집에서 사용합니다.
- 동적 생활 스킬 목록은 고정 품목 Y좌표를 사용하지 않고 exact OCR + 같은 행 아이콘 시각 신호 + 스크롤 재탐색을 사용합니다.
- 가방 100개 경로는 **확인된 생활 스킬 재료에서 화면 탐색이 실패했을 때만** 보조 경로로 사용합니다.
- 매핑이 없는 재료를 임의 생활 스킬/가방 경로로 추측하지 않습니다.
- 곤충 재료는 단독/자동가공 대량채집에서 직접 탐색하지 않고 제작 퀘스트 추천 획득처에서만 처리합니다.

## 자동 가공
- 기존 제법/대기열/7슬롯/재고 검증/중복등록 방지/이어하기 데이터는 유지합니다.
- 화면 입력은 공통 V3 runtime으로 통합했습니다.
- `설비로 이동` 클릭 뒤에는 게임 자동이동만 기다리며 **추가 Space를 누르지 않습니다.**
- 현장 도착은 가공 시설 화면 + `설비로 이동` 버튼 사라짐 + 이동 종료를 안정적으로 확인합니다.
- 품목 선택 및 작업 등록은 새 화면에서 확인된 상태만 사용합니다.
- 완료품 수령/완료 결과처럼 실제로 Space가 필요한 단계만 별도로 검증한 뒤 입력합니다.

## 생활 스킬 및 곤충 규칙
- 물이 든 병은 우물을 우선합니다.
- 버섯 포자는 `○○ 버섯 포자 → ○○ 버섯` 규칙을 사용합니다.
- 추수는 밀/옥수수/콩/쌀/귀리, 호미질은 감자/양파/조개/파스닙/양배추/호박/개암 버섯의 확인된 동일명 매핑을 사용합니다.
- 확인된 곤충 재료 `유령 반딧불이 / 석양 나비 / 흰얼음풍뎅이 / 낙엽나방 / 황혼잠자리`는 제작 퀘스트 전용으로 표시합니다.

## 안전 및 검증
- `execute_gathering`, `execute_altering`, `execute_crafting` 등 정령의 날개를 소모할 수 있는 CLI 액션은 계속 프로세스 경계에서 차단합니다.
- 실제 생산 성공 판정은 가능한 경우 CLI 재고/작업 조회를 기준으로 합니다.
- 기존 낚시·던전·어비스·F10·네트워크 복구·오류 전송·업데이트 롤백 기능은 유지합니다.
- Windows 빌드, 기존 회귀검사, 자동가공/자동채집/제작 회귀검사와 V3 구조 검사를 통과한 뒤 릴리스하도록 구성합니다.
- 실제 게임 UI는 사용자 환경에서 마지막 실동작 확인이 필요합니다.

# V2.0.6

V2.0.5 실게임 오류 로그 2건(17:39:21, 17:39:46)을 기준으로 제작 허브를 열기 전 화면 freshness 검사를 수정한 핫픽스입니다.

## 확인된 원인
- 오류 캡처는 둘 다 제작 허브가 아니라 움직이는 필드 화면이었습니다.
- 기존 코드는 상급 붕대 상세 여부를 OCR한 뒤, 같은 오래된 캡처와 현재 화면의 **전체 800×1000 프레임**을 다시 비교하고 K 입력을 허용했습니다.
- 필드의 캐릭터, 펫, 불꽃, 채팅처럼 정상적으로 움직이는 픽셀이 OCR 동안 2% 이상 바뀌면 `OCR 후 입력 대상 화면이 변경되어 입력을 정지합니다`로 중단되어 K 자체를 누르지 못했습니다.

## 수정
- 상세 화면 재사용 여부 OCR이 끝난 뒤에는 오래된 필드 전체 화면을 비교하지 않습니다.
- K(가공/제작 허브) 입력 직전에 새 800×1000 캡처를 다시 받아 창 위치·크기·포커스 안전검사를 갱신한 다음 즉시 K를 누릅니다.
- 실제 클릭 대상 OCR에는 기존 `RefreshInputFrame` 안전검사를 그대로 유지합니다.
- 로그에 `[제작] 제작 허브 열기 · K 입력 · fresh frame`을 추가해 다음 단계 추적이 가능하도록 했습니다.

## 기존 규칙 유지
- 아이템/음식 카드 compact OCR + 검증 좌표 fallback
- 검색의 `돋보기 → 입력칸 → 이름 입력 → Enter → 적용 → exact match`
- 제작 퀘스트, 직접 재료 추천 획득처, 중간재 자동가공
- 생활 스킬 100회 채집
- 설비 이동 후 불필요한 Space 미입력
- 정령의 날개 소모 CLI 실행 차단

# V2.0.5

V2.0.4 실게임 재테스트에서 제작 허브의 `아이템` 글자가 화면에 정상 표시되어 있는데도 Windows OCR이 해당 작은 제목을 읽지 못해 중단된 문제를 수정한 핫픽스입니다.

## 제작 허브 카드 선택
- 제작 허브 진입 후 먼저 화면 좌상단의 큰 `제작` 제목을 두 프레임에서 확인해 현재 화면이 제작 허브인지 검증합니다.
- `아이템 / 음식` 카드 제목은 작은 영역에서 compact OCR을 우선 사용합니다.
- 카드 제목 OCR이 두 프레임에서 정상 인식되면 실제 OCR 중심점을 클릭합니다.
- 실게임처럼 카드 제목 OCR만 실패하는 경우에는, 제작 허브 제목이 안정적으로 확인되고 카드 제목 영역에 밝은 텍스트 시각 신호가 두 프레임 모두 존재할 때만 800×1000에서 검증한 카드 중심 좌표를 fallback으로 사용합니다.
- 검증 좌표는 아이템 `(400,632)`, 음식 `(640,632)`이며 각 좌표가 해당 카드 내부인지 회귀 검사합니다.
- 이 fallback은 제작/결제 동작이 아닌 허브 내 카테고리 이동에만 사용합니다.

## 기존 규칙 유지

- 생활 스킬 목록은 개별 품목의 고정 Y좌표 대신 OCR 정확 이름, 같은 행 아이콘 영역 확인, 스크롤 재탐색을 사용합니다.

- 게임 내 아이템/재료/제작품 검색은 모두 `돋보기 → 입력칸 → 이름 입력 → Enter → 적용 → 정확한 이름 선택` 순서를 사용합니다.

- 메인 페이지에 품목 검색, 실제 CLI 목록 드롭다운, 목표 수량 입력, 시작 및 정지 버튼을 추가했습니다.
- 일반 시작 경로에서 설정 팝업을 제거하고 메인 화면의 선택 품목·수량을 그대로 전달합니다.
- 현재 재고, 도구·가공 가능 여부, 진행 수량·시간, CLI 및 캐릭터 확인 상태를 표시합니다.
- 자동 가공 진행 수량은 대기열 등록 건수 대신 실제 결과물 재고 증가로 표시합니다.
- 기존 CLI 실행 명령과 capabilities/get_my_info/get_currencies 검증, 낚시·던전·어비스 동작을 유지합니다.
- UI 회귀 테스트를 추가했습니다. 게임이 꺼져 있거나 조회에 실패하면 수량·연결을 임의로 정상 표시하지 않습니다.

## V0.1.94 변경 이력

V0.1.93에서 자동 가공/자동 채집을 별도 화면으로 분리하면서 생긴 UI 이질감과 메뉴 전환 문제를 수정했습니다.

## 기존 홈 UI로 통합

- 별도 ProductionDashboard 오버레이를 제거했습니다.
- 홈, 낚시, 던전, 어비스와 동일한 기존 대시보드 디자인을 그대로 사용합니다.
- 자동 가공/자동 채집을 눌러도 창 전체 UI가 다른 스타일로 바뀌지 않습니다.
- 홈 화면에서 자동 가공을 한 번 눌러 바로 선택할 수 있습니다.
- 자동 채집을 먼저 눌러야 자동 가공이 열리는 레이어/전환 문제를 제거했습니다.

## 표시 통일

- 사용자 표시명은 모두 `자동 가공`, `자동 채집`으로 통일했습니다.
- 자동 가공/채집에서는 기존 정보 카드가 작업 대상, 현재 단계, 진행 수량을 표시합니다.
- 하단 영역에는 기존 카드 스타일로 작업 설정과 CLI 실행 정보를 표시합니다.
- 시작 버튼은 선택 모드에 따라 `자동 가공 설정 / 시작`, `자동 채집 설정 / 시작`으로 표시됩니다.
- 진행률과 통계는 목표 수량 기준으로 계산합니다.

자동화 실행 로직과 CLI 검증 로직은 V0.1.93과 동일하게 유지합니다.
