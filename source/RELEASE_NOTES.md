# MABI AUTO V3.1.55 — 서버명 단독 CLI에서도 다중가공 새 테스트 시작

V3.1.54 현장 오류(2026-10-08 20:26)에서 `get_my_info`는 정상 연결됐으나 캐릭터 이름·고유 ID 없이 `RealmName` 하나만 제공했습니다. V3.1.54는 이 상황에서 F9 신규 작업조차 거부했습니다.

## 변경 사항 (PR #127)

- 최대 5회 조회 중 동일한 서버명만 일관되게 확인되면 **제한적 새 테스트** 경로를 제시합니다. 기본 버튼은 '아니요'이며 사용자가 '예'로 동의해야 진행합니다.
- 정상 고유 ID 또는 캐릭터 이름을 얻는 환경에서는 기존 N02 보호·이어하기 동작을 유지합니다.
- 제한적 테스트는 `%LOCALAPPDATA%\MabiAuto\multi-altering\limited-fresh-test\batch.json` 아래 별도 저장합니다. 기존 정식 `batch.json` 및 구형 `plan-*.json`은 변경하지 않습니다.
- **전체 가공 시설 대기 작업 0건**, 정식 미완료 배치 없음, 이전 제한적 미완료 테스트 없음, 저장 충돌 없음이 필요합니다.
- 제한적 테스트는 캐릭터를 안전하게 구별할 수 없어 **F10/재시작 자동 이어하기 불가**입니다. 이전 기록을 임의로 삭제하거나 자동 재등록하지 않습니다.
- N02 완료품목 중복 방지, F05 재료소비 기록, N03 입력 취소, 이동/수령 안전 검사는 유지합니다.

## 검증

- [PR #127 Windows CI](https://github.com/skwlrna/Mbi_auto_update/actions/runs/37771166461): 29개 전체 성공.
- 제한적 새 배치의 분리 저장, 미완료 재시작 거부, 기존 CLI 작업 존재 시 거부, 정식 배치 충돌 거부, 강한 식별 필수의 정상 배치 유지에 대한 회귀 테스트 추가.
- 이 테스트들은 모의 게임/CLI 및 Windows 빌드입니다. **실게임 동작 검증 완료를 뜻하지 않습니다.**

## 실게임 테스트 순서

1. 진행 중인 가공은 안전하게 중단하고 원본 저장 기록을 백업합니다. **구형 기록은 삭제하지 마세요.**
2. 프로그램을 V3.1.55로 업데이트 후, 모든 시설 대기 작업이 0건인지 확인합니다.
3. 이전에 처리된 품목과 수량이 겹치지 않게 소량의 **새 다중가공 작업**을 선택하고 F9를 누릅니다.
4. 제한적 새 테스트 확인창이 표시되면 설명을 읽고 신규 작업임을 확인한 뒤 '예'를 누릅니다. 기존 작업 이어하기가 아니라 **새 생산**입니다.
5. 중단하거나 재실행한 제한적 테스트는 자동 이어하기가 차단됩니다. 다음 테스트 전에 그 기록의 수령·완료 상태를 수동으로 검증해야 하며 임의 삭제하지 않습니다.
6. 다른 안전 오류가 발생하면 해당 시간의 GitHub 자동 오류 로그를 보존합니다.

이 릴리스는 **실게임 테스트용 후보**이며 완료·재시작 자동복구를 안전하게 보장하는 최종 버전은 아닙니다.
