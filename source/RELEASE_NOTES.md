# V3.0.22

자동 가공이 부족 원재료 채집으로 전환할 때 현장 가공 시설창을 닫지 않은 채 생활 스킬 C 입력을 보내던 문제를 수정한 패치입니다.

## 자동 가공 → 자동 채집 전환
- 가공 완료품 수령 뒤 목재/금속 등 가공 시설창에 남아 있으면 원재료 채집 전에 반드시 가공 UI를 종료합니다.
- 품목 상세가 남아 있으면 Esc로 상세창을 닫습니다.
- 가공 시설창이면 좌상단 뒤로가기로 가공 허브까지 나옵니다.
- 가공 허브에서는 Esc로 일반 필드로 복귀합니다.
- 가공 상세/시설/허브 표시가 모두 사라진 상태를 2프레임 연속 확인한 뒤에만 생활 스킬 단계로 넘깁니다.
- 화면 전환 중 알 수 없는 프레임에서는 임의 키를 누르지 않습니다.
- 이 종료 경로에서는 Space 입력을 절대 사용하지 않습니다.

## 생활 스킬
- 일반 필드 복귀 확인이 끝난 뒤 기존 V3.0.21의 C → 프로필 → 생활 스킬 확인 순서를 시작합니다.
- 생활 스킬 실패 시 가방/재료 상세 경로로 우회하지 않는 규칙은 유지합니다.

## 검증
- 가공 UI 종료가 생활 스킬 채집 시작보다 먼저 수행되는 순서를 CI에서 고정했습니다.
- 필드 복귀 루틴에 Space 입력이 다시 들어오지 않도록 회귀 보호 조건을 추가했습니다.
- Windows 빌드, 자동 가공/자동 채집/V3 production engine 및 기존 회귀 검사를 통과했습니다.

# V3.0.21

자동 가공/자동 채집의 부족 원재료 획득을 생활 스킬 경로로 고정하고, 제작 퀘스트의 마지막 재료 완료 후 게임 자체 제작대 복귀 흐름을 방해하던 추가 입력을 제거한 패치입니다.

## 자동 가공 · 자동 채집
- 대량 원재료 확보는 생활 스킬 100회 채집 경로만 사용합니다.
- C 입력 후 프로필에서 생활 스킬 메뉴가 실제로 보이는지 확인한 뒤에만 생활 스킬로 진입합니다.
- 생활 스킬 메뉴가 확인되지 않으면 제한 시간 내 재확인 후 오류로 정지하며, 가방 검색·재료 상세·구하는 방법 경로로 우회하지 않습니다.
- 생활 스킬 진입 실패 원인을 추적할 수 있도록 C 입력, 생활 스킬 메뉴 확인, 생활 스킬 진입 클릭 완료 로그를 추가했습니다.
- 설비 이동 및 채집 이동 중 불필요한 Space 입력 금지 규칙은 그대로 유지합니다.

## 제작
- 마지막 부족 재료가 충족되면 재료 확인을 위해 열었던 최상단 제작 퀘스트 상태를 그대로 유지합니다.
- 이후 별도의 제작대 복귀 단계 OCR/클릭을 수행하지 않고 게임의 자동 제작대 복귀를 기다립니다.
- 자동 복귀 중에는 퀘스트 추가 클릭, ESC, Space 입력을 하지 않습니다.
- 제작대 도착 후 자동으로 열린 제작창의 제작하기 버튼이 확인된 경우에만 Space로 제작을 시작합니다.
- 최초 퀘스트 생성 때 설정한 제작 수량을 그대로 사용하며 제작대 도착 후 수량을 다시 설정하지 않습니다.

## 검증
- Windows 빌드, 자동 가공·자동 채집·제작 및 V3 production engine 회귀 검사를 통과하도록 CI 보호 조건을 추가했습니다.
- 실제 게임 화면에서 생활 스킬 진입과 제작 퀘스트 자동 복귀의 최종 실동작 확인은 계속 필요합니다.

# V3.0.20

자동 가공 완료품 수령 경로의 Space 오동작을 막고, 제작 화면을 검색 전용 목록으로 단순화한 패치입니다.

## 자동 가공
- 기존 완료 작업을 수령할 때도 새 작업 등록과 동일하게 먼저 현장 가공대 도착 여부를 확인합니다.
- 원격 시설 화면에서 `설비로 이동`이 보이면 수령 Space를 누르지 않고 자동이동을 먼저 수행합니다.
- 현장 가공대는 시설 제목 표시 + `설비로 이동` 버튼 없음 상태를 연속 프레임으로 확인한 뒤에만 수령 Space를 허용합니다.
- 이동 확인 팝업의 초록 버튼을 가공 완료 결과창으로 오인하지 않도록 별도 이동 팝업 판정을 추가했습니다.
- `AutoTraveling=true` 상태에서는 완료 결과창 후보가 보여도 추가 Space를 차단합니다.
- 완료 결과창을 닫기 직전에도 활동 상태를 한 번 더 확인해 이동이 시작된 경우 입력하지 않습니다.

## 제작 UI
- 제작 탭의 `아이템` / `음식` 분류 버튼을 제거했습니다.
- 전체 제작 품목을 하나의 목록으로 표시하고 품목 검색으로만 찾도록 변경했습니다.
- 분류 정보가 없는 품목도 목록에서 숨기지 않습니다.
- 실제 제작 시작 시에는 선택한 품목의 CLI 분류 또는 이름 기반 폴백으로 게임 내 음식/아이템 제작대를 자동 선택합니다.

## 유지
- 목표 수량은 화살표 없는 숫자 입력을 유지합니다.
- 가공·채집의 기존 UI와 자동화 흐름은 유지합니다.
- 낚시·던전·어비스 UI는 수정하지 않았습니다.

# V3.0.19

런타임 오류 로그와 최신 제작 UI 문제를 함께 수정한 안정화 패치입니다.

## 제작
- 음식/아이템 분류 메타데이터가 실제 CLI에서 비어 있거나 대부분 누락돼도 두 탭이 모두 빈 목록이 되지 않도록 분류 호환 폴백을 추가했습니다.
- 폴백을 사용할 때도 한 품목이 음식/아이템 양쪽에 동시에 표시되지 않도록 한쪽에만 배정합니다.
- 마지막 부족 재료를 실제 가방 수량으로 충족한 뒤 퀘스트 팝업의 재료 수량 행이 사라지는 정상 상태를 OCR 실패로 처리하던 문제를 수정했습니다.
- 직전 읽기에서 부족 재료가 정확히 1개였고 그 재료가 현재 가방 수량으로 충족됐다는 근거가 있을 때만 재료행 없음 상태를 완료로 인정합니다.

## 가공
- 완료 결과창 확인 후 동일 시설 제목이 짧은 시간 안에 다시 보이지 않으면 바로 오류로 중단하던 문제를 수정했습니다.
- 시설 화면 복귀 확인을 더 오래 기다리고, CLI 가공 작업 수가 실제로 감소한 경우에도 수령 완료를 확정합니다.
- CLI 근거로 수령을 확정한 경우 다음 가공 진입에서 시설 화면을 다시 검증합니다.

## 채집
- 지역 이동/로딩 중 get_activity, get_items, get_inventory가 일시적으로 거절되는 경우 제작 재료 채집과 같은 방식으로 재시도합니다.
- 순수 자동이동 중에는 불필요한 재고 조회를 생략하고 이동 종료/채집 시작 후 재고를 다시 확인합니다.

## UI
- 가공·채집·제작의 목표 수량에서 NumericUpDown 스피너 자체를 제거했습니다.
- 위/아래 화살표를 숨기는 방식 대신 숫자만 입력 가능한 일반 텍스트 입력을 사용해 기존 화살표 자리의 잔상/이상 표시를 제거했습니다.
- 낚시·던전·어비스 UI는 변경하지 않았습니다.

V3.0.12 실게임 음식 제작 퀘스트에서 감자 추천 획득처 선택과 자동이동은 정상 시작됐지만, 이동/채집 중 `get_items`와 `get_activity`를 반복 조회하던 중 `get_items`가 한 번 `cli_rejected`를 반환하자 `가방 품목 수량 조회에 실패했습니다.`로 즉시 종료된 문제를 수정한 패치입니다. 실제 오류에서는 약 2초 뒤 같은 CLI가 다시 정상 조회로 회복되었습니다.

## 제작 퀘스트 이동/채집
- 자동가공 설비 이동과 같은 원칙으로 지역 이동/로딩 중 `get_activity`의 일시적인 `cli_rejected`를 오류로 확정하지 않고 재시도합니다.
- 자동이동·채집·낚시 또는 Stop 상태가 진행 중이면 재고용 `get_items` 조회를 생략합니다.
- 이동/채집이 끝난 뒤에만 감자 같은 퀘스트 재료의 실제 가방 수량을 확인합니다.
- 도착 직후 `get_items`가 로딩 때문에 일시 거절되면 500ms 간격으로 제한 재시도하고, 정상 응답이 돌아오면 그대로 계속 진행합니다.
- 로딩 거절이 아닌 CLI 오류, 안전하지 않은 필드 상태, 제한 시간 초과는 기존처럼 정지합니다.
- 필요한 수량을 충족하고 비활성 상태가 두 번 연속 확인된 뒤 다음 부족 재료로 넘어갑니다.

## 유지
- V3.0.12의 구하는 방법 팝업/추천 첫 행 좌표와 V3.0.11 재료 OCR 영역은 유지합니다.
- 자동가공·자동채집·Zero Wing 안전 규칙과 읽기 전용 CLI 원칙은 변경하지 않았습니다.

# V3.0.12

V3.0.11 실게임 음식 퀘스트에서 재료 수량 OCR은 정상 동작했고 `감자 7/80`을 읽어 감자 행까지 정상 클릭했지만, 이어서 열린 `구하는 방법` 팝업의 헤더 ROI와 추천 획득처 판정이 실제 화면 구조와 맞지 않아 중단된 문제를 수정한 패치입니다.

## 구하는 방법 팝업
- 실제 800×1000 오류 캡처에서 `구하는 방법` 제목은 약 y=560 부근에 있습니다.
- 기존 헤더 ROI `(45,230,560,180)`을 제거하고 실제 위치 기준 `(135,505,530,115)`을 사용합니다.
- 추천 첫 행은 약 y=650에 고정되어 있어 추천 행 영역 `(155,610,500,95)`과 클릭 좌표 `(400,650)`을 추가했습니다.
- 기존처럼 `호미질/채집` 같은 생활스킬 문자열이 OCR에 반드시 포함되어야 하는 조건을 제거했습니다.
- 두 프레임에서 `구하는 방법` 헤더와 `추천` 또는 해당 재료명이 안정적으로 확인되면 첫 번째 추천 행을 고정좌표로 클릭합니다.
- 팝업 닫기 판정도 같은 실제 헤더 ROI를 사용합니다.

## 이후 흐름
- 추천 행 클릭 후 게임 자동이동/채집 상태와 실제 재고 증가를 계속 확인합니다.
- 필요한 수량에 도달하고 이동/채집이 종료되면 다음 부족 재료로 넘어갑니다.
- 모든 재료가 준비되면 제작대 단계로 복귀해 기존 제작 완료 흐름을 계속 사용합니다.

## 유지
- V3.0.11 재료 팝업 ROI, V3.0.10 빠른 횟수 입력, 제작 완료창 확인 로직은 유지합니다.

# V3.0.10

V3.0.9 실게임 음식 제작 로그를 기준으로 제작 횟수 입력 전 긴 지연과 새 제작 퀘스트 오른쪽 목록 OCR 실패를 수정한 패치입니다.

## 제작 횟수 입력 속도
- 검색 첫 결과를 클릭한 뒤 제작 상세창 확인이 이미 끝난 상태에서 `SetCraftCountAsync`가 다시 `품목명 / 필요한 재료 / 퀘스트 만들기`를 전체 화면 OCR하던 중복 검사를 제거했습니다.
- 실제 로그에서 상세창 확인 `00:18:27.437` 후 횟수 설정 `00:18:45.259`까지 약 17.8초가 비던 원인을 제거했습니다.
- 상세창 안정화 대기는 250ms에서 100ms로 줄였습니다.
- 목표 1회는 버튼 입력 없음, 2회 이상은 기본 1회를 기준으로 `+`만 필요한 만큼 누릅니다.
- `+` 입력 간격은 70ms입니다.

## 새 제작 퀘스트 열기
- 퀘스트 생성 직후 오른쪽의 작은 주황색 제목을 OCR로 다시 찾는 경로를 제거했습니다.
- 실제 800×1000 화면에서 새 제작 퀘스트가 오른쪽 최상단에 고정 표시되는 위치 `(742,310)`을 사용합니다.
- `퀘스트 만들기` 직후 오버레이 정리 → 100ms → 오른쪽 최상단 퀘스트 클릭 → 300ms 후 재료행 OCR로 이어집니다.
- 기존 `야채볶음 제작` 제목/품목명/준비행 OCR 실패 때문에 팝업을 열지 못하던 경로를 제거했습니다.
- 제작대 복귀 단계에서 사용하는 퀘스트 단계 OCR 보조 로직은 유지합니다.

## 유지
- V3.0.8 제작 완료 결과창 확인 로직과 V3.0.9 제작대 도착 후 빠른 `제작하기` 처리는 유지합니다.

# V3.0.9

V3.0.8 음식 제작 퀘스트 테스트에서 퀘스트 생성은 성공했고 오른쪽에 `야채볶음 제작`, 재료 준비행, 음식 제작대 진행행까지 정상 표시됐지만 Windows OCR이 퀘스트 제목 전체를 한 줄로 반환하지 않아 중단된 문제를 수정한 패치입니다.

## 제작 퀘스트 오른쪽 목록 인식
- `야채볶음 제작` 전체 exact OCR을 우선 사용합니다.
- 전체 제목이 분리되어 읽히는 경우 오른쪽 퀘스트 영역에서 정확한 품목명 `야채볶음`만 확인돼도 같은 제작 퀘스트로 인정합니다.
- 품목명까지 놓친 경우에는 `재료명 준비 n/N` 행과 `○○ 제작대에서 제작 n/N` 행이 함께 존재하는 구조를 확인해 제목 위치를 추정합니다.
- 구조 fallback도 두 프레임에서 같은 위치가 확인된 경우에만 클릭합니다.
- 다른 품목명이 앞에 붙은 문자열은 동일 제작 퀘스트로 인정하지 않습니다.
- 제작대 복귀 단계 판정도 같은 제목 보조 인식을 사용하도록 통일했습니다.

## 제작 횟수 및 제작대 반응속도
- 제작 상세창은 기본 1회로 열린다는 실게임 동작을 사용해 `-` 9번 초기화를 제거했습니다.
- 목표가 1회면 횟수 버튼을 전혀 누르지 않습니다.
- 목표가 2회 이상이면 기본 1회를 기준으로 `+`만 필요한 횟수만큼 누릅니다.
- 제작 상세 안정화 대기를 250ms로 줄였습니다.
- 직접 제작대 도착 후 전체 상세 품목명 OCR을 다시 하지 않고 하단 `제작하기` 버튼만 확인합니다.
- `제작하기` 확인 폴링을 150ms로 줄여 버튼이 뜨는 즉시 Space를 누릅니다.

## 유지
- V3.0.8 제작 완료 결과창 확인 로직은 유지합니다.
- 검색/첫 결과/제작 상세/직접 제작 좌표는 변경하지 않았습니다.

# V3.0.8

V3.0.7 실게임에서 제작 자체는 정상 완료됐지만 결과창의 `제작 완료`/완성품명 OCR이 안정적으로 잡히지 않아 `확인`을 누르지 못하고 대기하던 문제를 수정한 패치입니다.

## 제작 완료 결과창
- 제작 시작 직전 완성품의 가방 재고 수량을 저장합니다.
- 제작 후 완성품 재고가 증가하면 OCR과 별개로 제작 완료 신호로 사용합니다.
- 결과창의 `제작 완료`와 하단 `확인`은 넓은 고정 ROI에서 보조 신호로 확인합니다.
- 완성품명 OCR은 더 이상 완료 판정의 필수 조건이 아닙니다.
- `제작 완료 OCR / 확인 OCR / 재고 증가 / 제작대 사용중→종료` 중 안정적인 완료 신호가 두 번 확인되면 Space를 눌러 결과창의 `확인`을 처리합니다.
- 결과창 확인 동작은 `Space` 1회이며, 완료 확인 후 600ms 대기합니다.

## 유지
- 제작대 도착 후 제작 횟수는 그대로 유지하고 다시 조절하지 않습니다.
- 검색/첫 결과/제작하러 가기 좌표와 1200ms 목록 안정화 대기는 유지합니다.
- 자동가공·자동채집·재료 부족 퀘스트 흐름은 변경하지 않았습니다.

- 재료 부족 시 기존 퀘스트/채집/중간가공 흐름은 변경하지 않았습니다.

## 공통 생산 엔진
- 제작·자동가공·자동채집이 공통 `ProductionUiRuntime`을 사용합니다.
- 오래된 OCR 캡처와 현재 **전체 800×1000 화면의 픽셀 변화율을 비교하는 방식은 생산 화면에서 제거**했습니다.
- OCR 클릭은 대상 ROI를 두 프레임에서 확인하고, 입력 직전 새 캡처에서 **같은 대상 ROI만 다시 읽은 위치**를 사용합니다.
- 필드의 캐릭터·펫·불꽃·채팅처럼 정상적으로 움직이는 요소 때문에 메뉴 단축키나 고정 UI 이동이 중단되지 않도록 했습니다.
- `ProductionStageMachine`으로 `허브 → 분류 → 검색 → 상세 → 퀘스트/재료 → 이동 → 처리 → 재고검증 → 완료` 단계를 명시적으로 기록합니다.
- 잘못된 숨은 단계 점프는 중단하며, 화면 복구는 검증된 허브 재진입으로만 수행합니다.

## 공통 검색
- 게임 내 제작품·아이템·재료 검색을 `ProductionSearchFlow` 하나로 통합했습니다.
- 검색 순서는 항상 `검색창 → 이름 입력 → Enter → 적용하기 → exact 결과`입니다.
- Enter 없이 Space나 적용을 먼저 누르는 검색 경로를 사용하지 않습니다.
- 제작 목록과 가방 보조 경로가 동일한 검색 규칙을 사용합니다.

## 제작
- 음식/아이템 공통 엔진, CLI `get_craftable_items` 목록, 최대 10회 배치 퀘스트를 유지합니다.
- 제작 허브의 음식/아이템 카드는 제작 화면을 확인한 뒤 검증된 800×1000 카드 위치를 보조 신호로 사용할 수 있습니다.
- 퀘스트 제목, 부족 재료 행, 추천 획득처, 제작대 복귀 단계는 저장된 과거 좌표를 바로 누르지 않고 새 프레임에서 재확인합니다.
- 직접 재료는 `제작 퀘스트 → 구하는 방법 → 추천 획득처`를 사용하고, 목표 수량 이상이면 완료로 처리합니다.
- 중간 가공품은 기존 자동가공 계산/재귀 해결기로 연결합니다.
- 제작 완료 화면은 목표 품목과 완료 표시를 다시 확인한 뒤 Space를 누르고, 실제 CLI 재고 증가량으로 배치 성공을 확정합니다.

## 자동 채집
- 단독 채집과 자동가공 원재료 확보는 **생활 스킬 100회 채집**을 우선합니다.
- 100회가 끝날 때마다 실제 CLI 재고 증가량을 확인하며, 100회=100개라고 가정하지 않습니다.
- 확인된 일상 채집/나무 베기/광석 캐기/약초 채집/양털 깎기/추수/호미질 매핑만 단독·대량채집에서 사용합니다.
- 동적 생활 스킬 목록은 고정 품목 Y좌표를 사용하지 않고 exact OCR + 같은 행 아이콘 시각 신호 + 스크롤 재탐색을 사용합니다.
- 가방 100개 경로는 **확인된 생활 스킬 재료에서 화면 탐색이 실패했을 때만** 보조 경로로 사용합니다.
- 매핑이 없는 재료를 임의 생활 스킬/가방 경로로 추측하지 않습니다.
- 곤충 재료는 단독/자동가공 대량채집에서 직접 탐색하지 않고 제작 퀘스트 추천 획득처에서만 처리합니다.

## 자동 가공
- 기존 제법/대기열/7슬롯/재고 검증/중복등록 방지/이어하기 데이터는 유지합니다.

- `설비로 이동` 클릭 뒤에는 게임 자동이동만 기다리며 **추가 Space를 누르지 않습니다.**
- 현장 도착은 가공 시설 화면 + `설비로 이동` 버튼 사라짐 + 이동 종료를 안정적으로 확인합니다.
- 품목 선택 및 작업 등록은 새 화면에서 확인된 상태만 사용합니다.
- 완료품 수령/완료 결과처럼 실제로 Space가 필요한 단계만 별도로 검증한 뒤 입력합니다.

- 물이 든 병은 우물을 우선합니다.

- 이 fallback은 제작/결제 동작이 아닌 허브 내 카테고리 이동에만 사용합니다.

- `설비로 이동` 클릭 뒤 확인 팝업으로 오인해 Space를 누르던 경로를 제거했습니다.

- 일상 채집, 나무 베기, 광석 캐기, 약초 채집, 양털 깎기, 추수, 호미질의 확인된 재료-채집 대상 매핑을 추가했습니다.
- `○○ 버섯 포자`는 `○○ 버섯`으로 변환해 찾으며, 개암 버섯 계열은 호미질로 처리합니다.
- 생활 스킬 목록은 개별 품목의 고정 Y좌표 대신 OCR 정확 이름, 같은 행 아이콘 영역 확인, 스크롤 재탐색을 사용합니다.
- 곤충채집은 독립 대량채집 대상으로 직접 탐색하지 않고 제작 퀘스트의 추천 획득처 경로에서만 사용합니다.
- 기존 가방 100개 획득 경로는 보조/fallback으로 유지합니다.

## 제작
- 음식/아이템 제작은 현재의 퀘스트 기반 최대 10회 배치 구조를 유지합니다.
- 제작 퀘스트에 뜨는 직접 재료와 곤충 같은 퀘스트 전용 재료는 `구하는 방법 → 추천 획득처` 경로로 확보합니다.

- 확인한 2번 스타일을 적용해 제목과 수량을 강조하고 둥근 입력창·카드·시작 버튼을 정리했습니다. 품목 및 도구 이미지는 표시하지 않습니다.
- 홈에서 자동 가공 또는 자동 채집을 한 번 클릭하면 해당 중앙 페이지만 표시합니다.
- 메인 페이지에 품목 검색, 실제 CLI 목록 드롭다운, 목표 수량 입력, 시작 및 정지 버튼을 추가했습니다.
- 일반 시작 경로에서 설정 팝업을 제거하고 메인 화면의 선택 품목·수량을 그대로 전달합니다.
- 현재 재고, 도구·가공 가능 여부, 진행 수량·시간, CLI 및 캐릭터 확인 상태를 표시합니다.
- 자동 가공 진행 수량은 대기열 등록 건수 대신 실제 결과물 재고 증가로 표시합니다.
- 기존 CLI 실행 명령과 capabilities/get_my_info/get_currencies 검증, 낚시·던전·어비스 동작을 유지합니다.
- UI 회귀 테스트를 추가했습니다. 게임이 꺼져 있거나 조회에 실패하면 수량·연결을 임의로 정상 표시하지 않습니다.

---

## V0.1.94 변경 이력

V0.1.93에서 자동 가공/자동 채집을 별도 화면으로 분리하면서 생긴 UI 이질감과 메뉴 전환 문제를 수정했습니다.

## 기존 홈 UI로 통합

- 별도 ProductionDashboard 오버레이를 제거했습니다.
- 홈, 낚시, 던전, 어비스와 동일한 기존 대시보드 디자인을 그대로 사용합니다.
- 자동 가공/자동 채집을 눌러도 창 전체 UI가 다른 스타일로 바뀌지 않습니다.
- 홈 화면에서 자동 가공을 한 번 눌러 바로 선택할 수 있습니다.
- 자동 채집을 먼저 눌러야 자동 가공이 열리는 레이어/전환 문제를 제거했습니다.

## 표시 통일

- 사용자 표시명은 모두 `자동 가공`, `자동 채집`으로 통일했습니다.
- 자동 가공/채집에서는 기존 정보 카드가 작업 대상, 현재 단계, 진행 수량을 표시합니다.
- 하단 영역에는 기존 카드 스타일로 작업 설정과 CLI 실행 정보를 표시합니다.
- 시작 버튼은 선택 모드에 따라 `자동 가공 설정 / 시작`, `자동 채집 설정 / 시작`으로 표시됩니다.
- 진행률과 통계는 목표 수량 기준으로 계산합니다.

자동화 실행 로직과 CLI 검증 로직은 V0.1.93과 동일하게 유지합니다.
