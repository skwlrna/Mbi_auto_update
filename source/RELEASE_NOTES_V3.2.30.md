# MabiAuto V3.2.30 — 자동가공 시설 누락 감시·재료 근거·로컬 오류 상태 기록

## 변경 사항
- 전역 `queue_full` 상태에서 타 시설이 7/7인데 선택한 식재료 등 독립 시설이 0/7로 계속 보류되면, 기본 2분 이후 **한 번만** 시설 누락 경고를 기록합니다. 이유/대상 변경 시 새 관찰 주기를 시작합니다. 진행 중인 시설은 이 감시에서 제외하며 실제 작업은 기존 CLI 타이머 기반 감시가 맡습니다.
- 새로운 자동 클릭이나 중복 가공은 금지합니다. 대기열 작업 ID가 없는 CLI 한계를 우회하지 않습니다.
- F9 선행채집 시 모든 선택 제법의 재료 근거를 별도로 남깁니다. CLI가 확정한 부족분과 `queue_full`에 가려진 미확정 재료를 구분합니다. 실제 재료 채집·중간 제작은 기존 원재료 합산/재귀 검증 엔진을 유지합니다.
- 다중가공 오류 시 읽기 전용 CLI 제법/시설별 작업 현황을 5초 이내로 재조회해 사용자 PC `%LOCALAPPDATA%/MabiAuto/diagnostics/altering`에 JSON을 기록합니다. CLI 조회 실패도 이유 유형만 기록하며 기존 오류는 보존합니다. 보관 개수는 최신 20개로 제한합니다.
- 오류 기록은 **로컬 전용**, 캐릭터 및 계정 식별자, 원시 패킷, 스크린샷, 전체 CLI 응답, 비밀번호/토큰은 기록하지 않습니다.

## 기존 안전조건
- F10 취소, 상태 불확실한 재개 차단, 시설 현장확인, 화면 검증, 정령의 날개 0개, 가공 등록 확인, 완성품 전체 수령 검증, 중간재료 소비 장부는 그대로 유지합니다.
- 직접 패킷 처리, 등록/수령 CLI 쓰기 명령, AI 자동 수정·병합 정책은 변경하지 않았습니다.
- 실제 게임 재현과 장시간 실사용 오류율의 개선 여부는 추가 검증 대상입니다.

## 검증
- 2분 경고 경계, 경고 한 번만 출력, 시설 재개/진행 때 감시 초기화
- 부족 재료 증거 vs. `queue_full` 가림 상태 구분
- 로컬 오류 기록 내용, CLI 조회 실패 메시지 노출 방지, 최대 20개 보관
- 기존 Windows CI 빌드와 다중가공/어비스/입력/저장 장부 회귀 테스트
