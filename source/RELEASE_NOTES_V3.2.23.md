# MabiAuto V3.2.23 — GitHub 오류 화면 기반 자동 가공·어비스 복구

## 수정 내역

- **가끔 나타나는 보관함 재료 전송 팝업**: 무료 가공 버튼 1회 클릭 뒤 `재료를 전송하시겠습니까?` 창이 나타나면, 창 제목·주간 체크 문구·확인 버튼을 두 화면에서 검사합니다. `일주일 동안 보지 않기`가 미선택이면 체크박스를 한 번 클릭하고 화면의 체크 변화 확인 후 `확인`을 한 번 누릅니다. 창이 없으면 기존 흐름을 유지합니다. 물음표가 OCR에서 빠진 경우에도 전체 제목을 확인합니다. 원래 CLI 작업 수 +1 확인, 중복 클릭 금지, 기존 대기 작업 기록을 유지합니다.
- **병행 어비스 퇴장 후 협동 미션 완료 창**: 정확한 문자 OCR이 실패하더라도 왼쪽 나가기 클릭이 별도로 검증된 경우에 한해, 트로피 문양과 제목·선물·확인 문자 영역 및 하나로 연결된 초록 확인 버튼을 두 화면에서 검증하여 `확인`을 한 번 누릅니다. 잘못된 팝업·3버튼 결과 화면은 제외하며 퇴장 후 필드 HUD 재확인은 계속 필요합니다.
- **AI 작업 공간 안전 정리**: 기존 ZIP/부분 ZIP 백업 이름이 존재하는 후보는 덮어쓰지 않고 사용자에게 충돌을 알립니다. 그 후보 때문에 다른 깨끗한 작업을 정리하지 못하는 문제를 해소합니다. 작업 수정안·오류 기록·기존 백업을 보존합니다.

## 실제 오류 근거

- 2026-10-17 00:34 KST 합금강괴 등록 중 보관함 재료 전송 팝업이 남아 CLI 등록 수 증가를 확인하지 못해 안전 정지한 오류 (V3.2.21).
- 2026-10-16 22:42 KST 병행 어비스 퇴장 후 `협동 미션 완료` 확인 화면이 남아 있고 OCR이 글자를 누락하여 90초 복구 제한에 도달한 오류 (V3.2.21).
- AI 작업 공간 정리에서 이미 보관 ZIP이 있을 때 다음 정상 후보를 고르지 못하는 문제.

## 배포 안전장치 및 검증 범위

- 세 수정 PR #225, #226, #227은 각각 GitHub Windows 생산 엔진 CI 및 어비스·가공 스케줄러 CI를 통과했습니다.
- V3.2.23 통합 소스는 **새로운 main CI가 성공한 정확한 커밋에서만** 빌드해 Windows Lite ZIP, SHA256, Source ZIP을 게시합니다.
- 게임 비용 사용 정책은 바꾸지 않았습니다. 재료 전송 창에는 게임이 표시하는 비용이 있을 수 있으며, 사용자가 승인한 팝업 확인 동작 외에 가공 버튼 자동 재클릭을 추가하지 않았습니다.
- GitHub CI는 실제 Windows 사용자 PC의 UI 인식/재료 소비/게임 플레이 성공을 대체하지 않습니다. 실제 게임에서 팝업 있음·없음·체크됨 및 미션 화면 복귀를 확인해야 합니다.
- 자동 업데이트는 실행 중인 게임이나 매크로를 임의로 종료·교체하지 않습니다. 기존 업데이트 롤백 스크립트와 이전 버전 보관 방식을 유지합니다.

## 설치 후 확인

1. 프로그램을 정상 종료한 뒤 자동 업데이트 또는 V3.2.23 Windows Lite 패키지를 적용하고 파일 버전 `3.2.23.0`을 확인합니다.
2. 일반 다중가공 및 보관함 재료 전송 팝업 발생 시 주간 체크·확인 1회, 동일 제법 작업수 +1 기록을 확인합니다.
3. 병행 어비스 종료 후 협동 미션 완료 화면에서 확인 1회 및 실제 필드 HUD 복귀를 확인합니다.
4. 문제가 반복되면 중복 클릭하지 말고 GitHub에 저장되는 오류 로그·스크린샷으로 진단합니다.
