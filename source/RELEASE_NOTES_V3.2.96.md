# Mabi Auto V3.2.96 — F9 독립 시설 대기 개선

## 실제 확인 및 수정 범위

2026-11-06 F9 /status에서 약품 시설 0/7, 상급 목재 7/7 진행, 식재료 7/7 진행, 금속 7/7 전체 완료가 함께 보고되었습니다. 표시된 마지막 동작은 상위 관리자 `병렬 대기`이므로, 이 기록만으로 약품 제법의 정확한 등록 거부 이유를 단정할 수 없습니다.

소스에서 별도로 확인된 구조적 문제는 재귀 중간재료 스케줄러가 다른 시설의 기존 진행 배치 완료를 **직접 대기**하며 상위 F9 관리자 실행을 점유할 수 있다는 점입니다.

- **새 다중가공에서 비어 있는 독립 시설을 첫 등록 1회씩 먼저 처리**해 첫 번째 시설이 7/7로 가득 차기 전에 약품 등 다른 제법에도 등록 기회를 줍니다. 이후 기존 7칸 묶음 정책을 유지합니다.
- **최초 중간재료 시설 경계**에서 기존 작업이 진행 중이면, 소유권 획득·수령·등록 없이 부모 F9에 제어권을 반환합니다.
- 부모 시설만 보류하고 **다른 독립 시설**의 평소 검증된 등록·묶음 수령을 진행합니다.
- 선행 시설의 작업이 실제로 완료되었는지 새로운 CLI 읽기로 확인한 후에만 부모 품목을 다시 시도합니다.
- 텔레그램 `/status`에 **조회 시점 제법 CLI Alterable/Reason**을 추가해 약품 0/7이 실제로 `queue_full`인지, 재료 부족인지 식별할 수 있게 했습니다.
- `queue_full`로 거부되고 부족 재료 증거도 없는 품목은 여전히 **임의 가공 버튼을 클릭하지 않습니다**.
- 기존 가공 좌표·이미지 인식, 소비 장부·작업 재개, 정령의 날개 비용, 가공 전체 완료 묶음 수령, 수동 F10 안전 정책을 유지합니다.

## 검증 및 배포

- Windows 빌드, 기존 가공·제작·채집·어비스 회귀, 신규 F9 독립 시설 위임/무입력 회귀 검사를 수행합니다.
- 정식 배포 전 **동일 main SHA**의 필수 Windows CI 성공, 자동 업데이트 ZIP SHA256, 실행파일 스모크, 롤백 스크립트를 검증합니다.
- **실제 게임에서 산뜻 버섯 진액 등록 성공은 아직 검증되지 않았습니다.** 적용 후 /status의 제법 CLI 사유를 확인해야 합니다.
- 현재 실행 중인 배치를 강제 종료하지 않으며 기존 자동 업데이트/롤백 절차를 유지합니다.
