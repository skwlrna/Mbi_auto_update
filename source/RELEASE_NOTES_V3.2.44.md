# MabiAuto V3.2.44 개발 후보 — 읽기 전용 반복 오류의 시설별 격리와 검증 복구

## 적용 범위
- **입력 전** F9 제법, 작업 대기열, 음식 재료 경로를 조회하던 읽기 전용 CLI가 임시 오류로 실패한 경우만 해당 시설을 30초 보류합니다.
- 준비된 독립 시설은 기존 장부·현장·화면 검증을 그대로 거쳐 계속 처리합니다.
- 동일 시설·제법·읽기 작업의 실패가 연속 2회 이상이면 반복 문제로 집계하고 제한된 로컬 JSON 진단 자료를 생성합니다.
- 재확인 시 신선한 읽기 전용 제법 식별과 시설 빈 대기열을 확인한 후에만 **재료 준비부터 다시 시작**합니다. 해당 진단 자체가 게임 입력 허가가 되지 않습니다.
- F10 중지 및 새 프로그램 재시작은 기존 명시적 재개/캐릭터 확인 정책을 따릅니다. 격리의 메모리 정보로 완료 기록을 복원하거나 자동으로 화면 조작하지 않습니다.

## 절대로 시설별 격리하지 않는 오류
- 가공 시설에 기존/완료 대기열이 존재해 수령 여부가 불확실한 상황
- 화면 이동, 가공/채집 등록 또는 수령 등 **게임 입력 이후**의 오류 및 결과 불명확
- 캐릭터 또는 제법/시설 불일치, 현장 소유권 모호, CLI 데이터 손상, 외부 대기열 변동
- F10/취소, 자동 업데이트 또는 보안 정책 위반
- 전역 CLI 읽기나 장부 자체의 오류로 입력 안전성을 증명할 수 없는 상황

위 오류는 기존대로 **전체 안전 정지 + 원인 분석**입니다. 원래의 read-only 재시도는 최대 1회이고 게임 입력 재시도는 추가하지 않았습니다.

## AI AutoFix 진단 연동
- 반복 실패와 신규 읽기 회복 시 로컬 `MabiAuto/diagnostics/altering/quarantine-*.json` 형태로 타입·시설·품목·횟수·시각만 저장합니다.
- 계정/캐릭터 ID·비밀번호·원시 패킷·전체 예외 문자열·화면 좌표는 저장하지 않습니다.
- 최근 20개까지 로컬 보존합니다. **기존 MCP 오류 감시기가 별도의 오류 이벤트를 접수해 AutoFix 분석을 시작할 때** `autopilot.py`가 최근 48시간의 반복 읽기 격리 기록 중 **허용된 시설 이름·읽기 작업 종류·횟수만 최대 3건** 분석 문맥에 추가합니다.
- 기록된 품목명·원문 예외·기타 JSON 키·임의 명령·원시 CLI 정보는 **AI 프롬프트에 전달하지 않습니다**. 기호가 섞인 작업 태그나 거짓 game-action 권한도 거부합니다.
- 격리 이벤트 **자체가 Codex/AutoFix 작업을 새로 만들지는 않습니다**. 기존 오류 이벤트가 생긴 경우의 참고 자료일 뿐이며 코드 수정/테스트/PR 생성/배포 및 게임 조작은 기존 별도의 제어 정책을 따릅니다.
- 실패해도 과거 입력의 성공을 추정하지 않으며, 진단 기록 삭제는 복구 허가와 무관합니다.

## 자동 검증
- 같은 읽기 실패 2회 격리/다른 시설 완료/새 제법·대기열 증명 후 복구
- 불확실 상태, 기존 가공 작업 존재, 화면 입력 결과 불명확 시 전체 안전 정지
- F10 취소, 비밀정보 없는 진단 파일
- 이전 3.2.41~43 재료 보류/재고 예측/효율 우선순위 및 Windows 빌드 검증
