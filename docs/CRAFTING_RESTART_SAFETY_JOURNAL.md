# 제작 중단·재시작 중복 실행 보호 (검증용 PR)

## 목적

V3.2.87까지의 제작 화면 엔진은 같은 실행 중에는 완료 화면과 CLI 재고 증가량을
검사하지만, F10/프로세스 종료 이후에는 이전 제작 배치의 완료·미확정 기록을
재시작과 연결하지 않습니다. 새 F9에서 동일 품목의 **전체 목표 수량**을 새로
실행하면 이미 생산된 수량과 중복될 수 있습니다.

이 변경은 자동 이어하기 기능이 아닙니다. **확실하지 않은 제작 입력은
복원하거나 재클릭하지 않고, 새 제작을 사용자가 명시적으로 승인해야만 시작**
하도록 합니다. 기존 게임 입력·제작 반복·30초 OCR 재시도·F10의 취소 동작을
바꾸지 않습니다.

## 기록과 생명주기

- 저장소: `%LOCALAPPDATA%\MabiAuto\crafting\restart-safety.json`
- 잠금: `restart-safety.lock` (동시에 한 실행만 허용)
- 이전 실행 보관: `crafting\reviewed\<run-id>.json`
- 사용자 정보: 기존 CLI에서 읽힌 캐릭터 식별 문맥. 비밀번호나 토큰 미저장.
- 기록 범위: 제작 품목·목표·순번, 완료/건너뛴 순번, 제작 클릭 직전의
  재고 및 배치 수, **검증된 재고 증가량**, 배치별 확정 수량, 종료 상태.
- 기록은 같은 폴더의 임시 파일 작성 후 교체하며, 쓰기 실패/손상/미확정
  임시 파일은 입력을 허용하지 않습니다.
- 입력 가능성 있는 제작 동작 이전에 **미확정 배치 의도**를 저장합니다.
  제작 완료 팝업 및 기존 CLI의 증가량 검증이 성공한 뒤에만 확정 기록을
  저장하며, 기록 저장에 실패하면 다음 제작으로 진행하지 않습니다.
- 모든 품목이 목표를 달성한 경우에만 종료 기록을 완료로 변경합니다.
  재료 부족으로 품목을 건너뛰었거나 F10/강제 종료한 경우는 미완료 상태로
  남습니다.

## 사용자에게 보이는 행동

1. 정상 완료된 이전 실행만 있다면 다음 F9 새 목표를 기존처럼 시작합니다.
2. F10/비정상 종료/미확정 클릭/건너뛴 품목의 기록이 남으면
   **기본 선택이 '아니요'인 경고창**을 띄웁니다.
3. '아니요'를 누르면 제작 입력 없이 중단합니다.
4. 게임 내 실제 재고·퀘스트를 사용자가 직접 확인하고 **완전히 새로운 목표**로
   제작할 것을 승인한 경우에만 '예'를 선택할 수 있습니다. 이때 이전 기록은
   `reviewed` 폴더에 보관하고 새 실행을 시작합니다. 이전 잔량을 자동
   계산하거나 이전 게임 클릭을 재실행하지 않습니다.

사용자가 같은 전체 목표를 그대로 새 작업으로 승인하면 중복 제작될 수 있으므로,
**수동 확인 없이 '예'를 선택하면 안 됩니다.** 장부는 독립적으로 게임의
실제 상태를 입증할 수 없으며, 멀티캐릭터·외부 수량 변동까지 자동
판정하지 않습니다. 기록 손상이나 임시 파일 잔류는 자동 초기화하지 않습니다.

## 오프라인 회귀

`tests/crafting/Regression.csproj`의 다음 테스트를 추가합니다.

- 클릭 직전 기록을 남긴 채 프로세스가 종료될 때 새 F9의 무승인 재시작 차단
- 사용자 승인 토큰/기존 기록 일치, 이전 의도 보존 및 새 실행 크레딧 초기화
- 재고 증가 증거가 부족한 미확정 배치 차단
- 완전히 확인된 제작 목표만 완료 인정
- 하나 이상의 품목이 건너뛰어지면 미완료 기록 유지
- F10이 클릭 전에 발생한 상태도 새 시작 시 검토 필요
- 동시 실행 잠금, 손상된 장부/미확정 임시 파일에서 안전 정지
- 실제 `CraftingAutomation.RunAsync` 모의 화면의 10/10/3 제작과,
  출력 미확정 후 취소에서 미확정 기록 보존

오프라인 Windows 빌드와 회귀 테스트만 수행합니다. **실제 게임 실행,
공식 릴리스, 자동 병합 및 어비스 기믹 변경은 하지 않습니다.**
