# 흩어진 물길 1·3번방 관측 우선 자동화 설계

## 범위 및 확인한 기존 코드

이 변경은 소스 3.2.23 기반 **순수 상태·전략 코어 및 회귀 테스트**만 추가한다. 실제 게임 입력은 비활성 상태다. AI 커넥터는 사용하지 않는다.

현재 저장소에서 확인한 기반:
- dungeon/WindowCapture.cs, TargetDetector.cs, OcrRecognizer.cs: 캡처/화면 인식
- dungeon/ScenarioEngine.Abyss*.cs: 어비스 결과 및 퇴장 처리
- abyss/templates/scene_skip_phone.jpg, touch_screen.png: 장면 넘기기·결과 문구 이미지
- abyss/config/scenario.json: scene_skip 반복 감시 및 abyss_touch_screen 결과 대기
- dungeon/InputController.cs: TapScanCode 및 기존 마우스 입력

현재 저장소에서는 **투창·주술사·O/X용 검증된 패킷 디코더나 세계 좌표 공급자**를 확인하지 못했다. 게임 패킷 ID, 데이터 오프셋/구조는 설정하지 않았다. 기존 입력은 신규 기능이 요구하는 장시간 키다운/키업 유지 계약도 아직 충족하지 않는다.

## 정규화 관측 계약

허용된 수신 패킷에서 반복 검증한 실제 관측값: AllowedReceivedPacket.
화면 이미지/OCR에서 검증한 값: Screen.
궤적, 좌표 보간, 게임 공략 가설: Inference.

각 관측에는 로컬 관측 시각, 출처, 설명, 해당 입장/대상 식별 정보가 있어야 한다. 상태 전이와 기믹 성공은 직접 관측값으로만 인정한다. 위치 유효시간은 측정된 데이터 주기와 지연에 따라 구성한다. 임의의 **이동 완료 시간 제한**을 두지 않는다.

## 상위 상태

1. Room1Spear: 새 입장이 관측된 후 시작
2. Room1Cleared: 관측된 투창병·주술사 처치 및 문 열림
3. Room2Combat: 2번방 전투 진입
4. Room2Cleared: 2번방 종료와 다음 통로 진입 확인
5. Room3Tiles: 테로사 3×3 발판 진입
6. BossDefeated: 테로사 처치 확인
7. ResultPrompt: 화면 터치 결과 문구 확인
8. RewardConfirmed: 실제 보상 화면 확인

ScatteredWaterwayFlow는 순서대로만 전이한다. 방 종료·보상 상태에서 옛 조준 신호로 역행하지 않는다. 새로운 내부 입장 nonce는 **실제 신규 입장 확인 시에만** 발급한다. entryEpoch, 이벤트 시각과 현재 단계 진입시각을 비교하여 늦은 이벤트를 차단한다. 상위 복합 조건(처치+문 열림 등)은 런타임 관측 어댑터에서 각각 직접 확인해야 한다. 기존 어비스 결과/퇴장 상태 머신과 연결할 때 이중 클릭을 방지해야 한다.

## 1번방 세부 순서

조준 대기 → 내 객체 ID와 조준 대상 일치 → 같은 속성 보호막 주술사 선택 → ASSIST OFF 확인 → 뒤쪽 목표점으로 이동/연속 정렬 → 실제 적중/보호막 변화/그로기 확인 → 다음 조준 또는 방 종료 대기.

- 목표점: M + normalize(M-S) × 측정한 뒤쪽 거리
- 조준 대상·창 속성·주술사 생존/보호막·세 객체 위치에 유효하고 최신인 직접 관측이 없으면 목표점을 만들지 않는다.
- 가까운 주술사를 선택하더라도 실제 피격 판정은 별도 관측으로 검증한다.
- 기하 정렬은 실제 피격 성공이 아니다. 창이 발사됐다는 사실도 성공이 아니다.
- 성공은 선택된 주술사 ID에 대한 적중·보호막 변화·그로기·처치의 직접 근거로만 판정한다.
- 한 번 적중과 방 종료는 구분한다.

## 3번방 세부 순서

현재 9칸 읽기 → 내 O 차례·나를 배치 대상으로 지목한 사실 확인 → 우선순위 결정 → ASSIST OFF 확인 → 발판 중앙 이동 → 도착 후 키업 → O 확정 기다리기 → 자동스킬 ON/퀘스트 재개 → 다음 턴 재관측.

선택 우선순위: O 즉시 승리 > X 즉시 승리 방어 > 빈 반대 대각 모서리(중앙에 X가 없고 이전 내 O 모서리가 확인된 경우) > 다른 빈 모서리 > 중앙 > 변.

이 공략의 “테로사는 중앙에 X를 놓지 않는다”는 버전별로 **재검증해야 할 가설**이다. 실제 X가 중앙에 오면 기존 가설에 따른 반대 대각 선점의 우선순위를 제거한다. 관측된 중앙 X를 무시하지 않는다. 파티원이 놓은 O도 승리 판단에 포함한다.

발판 도착과 O 확정은 다르다. 보드가 O로 바뀐 사실만으로 내가 놓았다고 추정하지 않는다. 보드 확정 자료와 내 선택 플레이어 근거를 모두 확인한 뒤 내 모서리 이력을 갱신한다. 관측된 판 초기화가 아닌 한 기존 O/X가 뒤바뀐 값을 받아들이지 않는다. O 승리는 보스 처치나 보상 확인을 의미하지 않는다.

## 공통 입력/안전 조건

- H는 토글: ASSIST ON이 직접 보일 때 OFF 요청으로 **한 번** 누르고 OFF를 기다린다. 상태 Unknown 또는 토글 미확정이면 다시 누르지 않는다. 성공 후에도 반대로 확인하며 ON을 만든 뒤 퀘스트 트래커를 클릭한다.
- 이동은 키 집합을 유지(예: W+D 동시 유지)하고 새 좌표에 따라 변경하는 방식이다. TapScanCode 반복은 사용하지 않는다.
- W, D 각 입력으로 측정한 세계 좌표 변위를 이용해 카메라 방향을 보정한다. 측정 없으면 이동하지 않는다.
- 사용자 조작, 시점 변경, 구형 좌표, 대상 사라짐, 화면 전환, 취소·예외 시 이동 키를 해제한다. 사용자 개입 종료 후 입력 축 재검증을 거친다.
- 목적지 판정은 측정된 도착·이탈 반경을 달리하는 히스테리시스 방식이어야 한다.
- 장면 넘기기가 보이면 이동 키를 놓고 우선 처리한다. 클릭 후 같은 위치에 문구가 남아 있으면 다시 처리한다. 배경 픽셀 차이만으로 취소하지 않는다.
- 화면을 터치해 주세요 이후 기믹 입력을 종료하고 실제 보상 화면까지 관찰한다.

## 회귀 실행

dotnet run --project tests/waterway/Regression.csproj -c Release

검증 범위: 입장 epoch·단계 역행 차단, 화면/패킷/추정 구분, 투창 목표·요소 일치·적중 근거, O/X 승리·패배방어·파티 O·중앙 X 예외, 키 유지/사용자 양보, H 오토토글 중복 금지.

테스트 통과가 실게임 성공이나 패킷 식별 완료를 의미하지는 않는다.
