# 20단계 — 가공·제작·낚시·일반 던전의 기존 검증 화면 연결

## 목적
19단계의 읽기 전용 화면 진단을 기존 네 자동화 기능으로 확대한다.
새 화면 캡처, OCR, CLI 조회, 패킷 파싱, 키 입력, 자동 복구 또는 원격 AI 실행을 추가하지 않는다.
개발 PR #231 전용 변경이며 main/운영 릴리스에 자동 적용하지 않는다.

## 검증 후에만 기록되는 신호

| 모드 | 이미 존재하는 생산 안전 검사 | 오류 진단 표식 | 절대 확정하지 않는 내용 |
| --- | --- | --- | --- |
| 가공 | `AlteringScreen`의 무료 버튼·레시피 상세·시설 현장 여부·최신 좌표 재검증 후 | `altering_free_action_guard_passed` | 등록 성공, 재료 소비, 완료, 수령 |
| 제작 | `CraftingScreen`의 완료 팝업 2프레임 + 직전 fresh 프레임 확인 후 | `crafting_result_popup_guard_passed` | 서버 제작 성공·인벤토리 수령 |
| 낚시 | `FishingBot`의 낚싯대 아이콘 점수·크기 2프레임 확인 후 | `fishing_hook_ready_two_frames` | 입질, 조과·보상·완료 |
| 일반 던전/페카 심층 | `ScenarioEngine`의 정확한 재시도 OCR 2회, 입장 화면 배제, 마지막 새 화면 위치 재확인 후 | `dungeon_retry_guard_passed` | 보스 처치, 던전 클리어, 재시도 클릭 성공 |

어비스는 해당 일반 던전 후크에서 `!IsAbyss`로 제외한다. 기존 19단계 어비스용 신호만 유지한다.
위 네 신호에 대응하는 검증된 독립 CLI 상태 비교는 현재 없다. 화면+임의의 CLI 정상 응답을
`independent_sources_agree`로 올리지 않으며 항상 `comparison=no_comparable_cli_state`다.
유일한 CLI 비교 가능 신호는 19단계의 채집 진행 관측이다.

## 구현 원칙

- 성공한 **기존** 화면 안전 검사에 후속 `ObserveVerifiedScreen` 호출 한 번만 추가한다.
- 사후 진단이 예외를 던져도 기존 매크로의 안전 정지·클릭·동작을 변경하지 않는다.
- 사용자가 켜 둔 기존 AI 오류 감시기에서만 캐시하고 꺼지면 지운다.
- 이벤트의 고정된 종류 + UTC 시각만 남긴다. 스크린샷/OCR/아이템·제법명/좌표/캐릭터명/ID 저장 없음.
- 기존 오류 발생보다 늦은 이벤트와 5초 초과의 이벤트, 다른 기능 범주, 알 수 없는 신호는 무시한다.
- 전체 화면 진단 블록은 `verified_cause=false;gameplay_authorized=false;repair_authorized=false`이며 진단 참고만 한다.
- 15단계 A/B는 18·19·20단계의 허용된 버전 블록만 Before에서 제외하고, 스키마 위조·중복·5초 초과를 거부한다.
- 같은 가공/제작/낚시/일반 던전 내에서도 근거 의미가 다른 임의 상태로 확대하지 않는다.

## 검증
`tests/common-observation/Stage20Tests.cs`: 정확한 모드 매핑, 페카 심층, 옵트인 전후,
다른 자동화 분리, 비연관 CLI 조회가 만든 가짜 독립적 합치 차단,
오류 이전 5초, 오류 이후 자료 배제, AI 감시기 종료 후 캐시 제거, 권한 불가를 합성 시험한다.

`tests/ai-autopilot/test_evidence_ab_stage15.py`: 네 신호의 고정 블록이 동일 오류의
Before에 영향을 주지 않는지, 중복·거짓 승인값·위조된 신호/비교값·범위 밖 시간을 거부하는지 확인한다.
Windows 빌드 및 기존 자동화 회귀 테스트 결과와 실제 게임 테스트는 분리해 평가한다.

## 후속
다음 단계는 실제 오류 로그의 감지량과 거짓 긍정을 평가하기 위한 집계 규칙/가드부터 점검한다.
검증된 근거 없이 실게임 오류율 감소나 AI 원인 진단 향상 수치를 주장하지 않는다.
