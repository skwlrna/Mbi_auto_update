# 15단계 — AI 오류 증거 Before/After 비교

## 범위

14단계에서 기존 읽기 전용 CLI 조회 결과를 오류 발생 시점의 비식별 증거로
첨부하도록 만들었다. 15단계에서는 **같은 오류**를 기준으로, 그 진단 블록이
없을 때(Before)와 있을 때(After)의 증거 범위와 기존 휴리스틱 분류 차이를
오프라인에서 검사한다.

새 진단기: source/FishingAutomation/ai-autopilot/evidence_ab.py

- 게임, CLI 실행 파일, Codex, 외부 서버, 네트워크, 화면 또는 자동 입력을 실행하지 않음
- 기존 오류 보고서, 수정 작업공간, AI 결과, 배포 설정을 변경하지 않음
- 기본 사용자 폴더의 로컬 오류 기록에서 error.txt만 확인
- 한 파일 최대 16KiB, 총 200개 폴더. 링크·형식 오류·대용량 파일 거부
- 보고서 출력은 정해진 **건수와 분류 이름만** 허용하며 캐릭터, 아이템, 계정,
  파일 경로, 오류 상세 원문은 출력하지 않음

## 비교 방법

1. BEGIN READ-ONLY CLI DIAGNOSTIC / END READ-ONLY CLI DIAGNOSTIC
   표시와, 내부 쿼리·값·순서·5초 유효시간을 엄격하게 검사한다.
2. 유효하다면 진단 블록만 뺀 원본 텍스트를 Before, 포함한 텍스트를
   After로 삼는다. 원래 오류 설명은 두 경우 동일하다.
3. 기존 error_memory.classify의 결정적 **추정** 분류를 비교한다.
   결과가 바뀌면 potential_heuristic_label_bias로 측정한다.
4. 연결·CLI 조회 실패, 가공 중, 채집 중, 수령 미확인, 인벤토리 수량 변화
   미확인 등의 비식별 **보조 힌트** 존재 건수를 측정한다.
5. 블록이 없거나 변조됐으면 자료 없음 또는 유효하지 않음으로 구분한다.

중요: 새 진단 문구 안에 "receipt" 또는 "CLI" 같은 단어가 추가되면
기존 단어 기반 오류 분류가 바뀔 수 있다. **분류 변화는 정답률 향상이 아니다.**
이 도구는 그러한 편향 가능성을 탐지할 뿐, 모델의 원인 분석 품질을 증명하지 않는다.

## 로컬에서 한 번만 실행하는 방법

개발 코드가 사용자 PC에 준비된 뒤 아래 명령을 실행할 수 있다.

    python source/FishingAutomation/ai-autopilot/evidence_ab.py

이 명령은 기본적으로 현재 사용자 프로필의
MabiAutoAI/runtime-reports 폴더를 읽고 JSON 집계만 콘솔에 표시한다.
기존 버전의 과거 오류에는 진단 블록이 없으므로 valid_reports=0일 수 있다.
실제 사용자 PC에서 이 명령을 실행한 적은 **아직 없다.**

## 완료 의미와 미검증 사항

이번 단계에서 검증 가능한 것은 **보조 증거 수집의 가용성·형식 정확도 및
기존 휴리스틱 분류가 보조 문구에 흔들리는지 여부**다.

아직 검증하지 못한 것은 실시간 패킷의 게임 이벤트 의미, Codex의 원인 분석
정답률, 실제 오류율·자동 복구율·복구 시간의 변화다. 이 내용은 실제 오류 한 건과
독립적인 성공/실패 근거가 확보될 때만 실사용 A/B로 검증할 수 있다.

사용자 PC에서 실전 검증할 때에는 AI의 추정 설명을 정답으로 간주해서는 안 된다.
기존 격리 작업공간·실제 회귀 테스트·사용자 검토 Draft PR·롤백 정책을 유지한다.
