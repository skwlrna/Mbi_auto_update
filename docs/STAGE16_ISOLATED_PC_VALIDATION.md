# 16단계 — 운영 매크로와 분리된 PC 검증용 실행 파일

## 구현 내용

Stage 16 빌드는 Stage 11–15의 읽기 전용 CLI 관측과 AI 오류 증거
**형식**을 사용자 PC에서 한 번 확인하기 위한 독립 Windows x64
진단 GUI다. 개발 PR #231에만 포함된다.

일반 모비매크로 실행 파일과 같은 소스 트리에서 빌드하지만,
MSBuild 속성 `Stage16PreviewOnly=true`일 때만
`STAGE16_PREVIEW_ONLY` 조건이 활성화되고 `Program.Main()`은
`Stage16ReadOnlyPreviewForm` 하나만 실행한다.
`MainForm`, 낚시·채집·가공 자동화, 던전 실행, 단축키,
업데이트 검사·설치, 텔레그램 제어, AI 감시/Codex 시작,
패킷 캡처를 호출하지 않는다.

평소 `Stage16PreviewOnly`는 지정하지 않으며
운영 실행 파일의 엔트리포인트는 변경되지 않는다.

## 사용자 절차

1. GitHub Actions의 **Read-only packet observation checks** 완료 기록에서
   `MabiAuto-Stage16-Isolated-ReadOnly-Win64` 아티팩트 ZIP을 받는다.
2. 기존 운영 매크로 폴더가 아닌 **새 폴더**에 압축을 해제한다.
3. 기존 모비매크로를 **종료**한다. 게임 클라이언트는 켜 둬도 된다.
4. `Run_Stage16_ReadOnly.cmd`를 더블클릭하고 Y를 선택한다.
5. 열린 테스트 창에서 **CLI 1회 확인**을 클릭한다.
6. `연결`, `활동·채집`, `가공 작업`, `인벤토리 형식`,
   `가공 레시피 형식`의 **비식별 상태 분류**만 확인한다.
7. 오류가 있으면 **분류 코드·테스트 시각만** 기록한다. 캐릭터명,
   아이템명, CLI 원문, 패킷 바이트, 토큰, 로컬 파일 경로는
   전달하지 않는다.

런처에서 N을 고르거나 실행 창만 열면 CLI 호출은 0회다.
실제 GUI 버튼을 누른 경우에만 기존 허용된 5개 CLI 조회를 한 번씩
시도하고, 종료하면 메모리 관측을 삭제한다. 같은 이름의 별도
매크로 프로세스가 발견되거나 프로세스 검사가 불가능하면
조회는 보류된다. **이 검사로 다른 이름의 모든 매크로를 탐지할 수는
없으므로 기존 매크로를 직접 종료한 뒤 실행해야 한다.**

테스트 중 AI 오류 증거를 모의 확인할 때에도 오류 파일을 만들거나
Codex에 데이터를 보내지 않는다. 실제 AI 파이프라인 검증이
완료됐다는 뜻이 아니다.

## GitHub 빌드/테스트

GitHub Actions의 기존 Read-only packet observation workflow에 추가:

- 기본 Windows 앱 빌드와 독립 정책 C# 회귀 검사를 유지한다.
- Stage 16 진단 전용 WinForms 빌드를
  `dotnet publish ... -p:Stage16PreviewOnly=true`로 생성한다.
- EXE를 `--stage16-self-test`로 실행해 GUI·CLI·게임을 전혀 열지 않고
  명시적 동의 정책을 확인한다.
- 실행 패키지는 **EXE / CMD / 사용안내 TXT만** 허용한다.
  운영 `config.json`, `notification.json`, 파이썬 AI 설정,
  업데이트 파일, 프라이빗 로그, 템플릿을 포함하지 않는다.
- 생성된 GitHub Actions ZIP 아티팩트는 14일간 보존된다.
- 기본 운영 버전 및 `main`에 병합·릴리스하거나 사용자 PC에
  자동 설치하지 않는다.

## 판정의 한계

이 패키지는 **실제 CLI 한 번 조회가 가능한지**와 정상/실패
카테고리가 화면에서 어떻게 표시되는지를 사용자 PC에서 테스트한다.
모비레이 패킷 의미·좌표·실시간 전투 이벤트·중간재·가공 완료,
AI 원인 분석 정확도, 오류 감소율은 검증하지 않는다.

실제 사용자의 PC에서 실행한 결과는 아직 수집되지 않았다.
CLI 연결 성공이나 작업 행 완료는 수령 또는 안전한 게임 조작 근거가 아니다.
