# 23단계 — 22단계 익명 검토 순위를 기존 AI 오류 분석 참고 자료에 연결

## 목적

사용자가 이미 시작한 기존 `ai-autopilot/autopilot.py` AI 감시기에서 **실제로 오류를 분석할 때만**
21단계 로컬 집계를 읽고 22단계 고정 검토 순위를 추가 참고할 수 있게 한다.

추가된 정보는 오류 분석 입력의 **읽기 전용 참고 메타데이터**이며, 다른 오류를 먼저 처리하거나
Codex 실행 횟수·오류 원인 판단·코드 수정 범위·테스트 기준·배포 승인·게임 조작을 변경하지 않는다.

## 흐름

`autopilot.process()`가 기존 고정 소스 확인, 격리 환경 조건을 통과하고
`context_for(folder)`로 기존 오류 자료를 읽은 뒤:
 
1. `incident_review_context.for_runtime_error(folder, runtime_root)`가
   대상 폴더가 이미 허용된 `runtime_...` 이름의 *직속 로컬 오류 폴더*인지 확인한다.
   외부 MCP 폴더·링크·빈/손상/16KiB 초과 오류 파일은 차단한다.
2. 21단계 `incident_coverage_audit.summarize`는 기존과 같은 상한(폴더 최대 200개) 내에서
   원본 오류 파일을 **읽기만** 하며 22단계 `incident_priority_review.prioritize`는
   고정된 스키마와 건수 검증 후 검토 후보를 계산한다.
3. 내용이 검증되고 실제 점검할 항목이 있을 때만, 고정된 상위 3개 `P1`~`P4` 레이블과
   익명 건수를 *최대 750글자* 텍스트로 변환한다.
4. 기존 `prompt_for`의 `<untrusted-log>` 영역 안에서 원본 오류 참고 자료 뒤에만 첨부한다.
   Codex의 상위 지시나 권한 블록이 아니다.
5. 입력 자료가 없거나 잘못되었거나 데이터 읽기에 실패하면 기존 프롬프트가 **그대로** 사용된다.
   이미 실행 중인 오류 처리와 안전 종료 절차는 바뀌지 않는다.

버전 표식: `BEGIN AGGREGATE DIAGNOSTIC REVIEW V1` /
`END AGGREGATE DIAGNOSTIC REVIEW V1`

신호: `scope=global_aggregate_not_this_incident`.
기존 오류 **전체의 진단 자료 품질**을 점검하기 위한 신호이며
해당 사건만의 심각도나 진단 확신도가 아니다.

## 허용 범위

- Codex 프롬프트 하나에 읽기 전용 추가 주석을 연결한다. 기본 오류 증거와
  과거 AI 학습용 해시 특징 자료는 종전 경로를 그대로 유지한다.
- 원래의 Codex 첫 수정 요청과 자동 테스트 후 *기존 격리된 동일 작업공간 재수정* 요청에
  같은 익명 주석을 넣는다. 새 Codex 실행이나 새로운 자율 작업 큐를 생성하지 않는다.
- 기존 watcher의 최신 오류 우선, 동일 오류 dedup, AI quota 확인,
  clean repo / pinned source / isolated mode 조건, 고정 파일 경로,
  실제 등록 테스트와 diff 검증, 사용자 승인/수동 배포가 필수인 규칙을 변경하지 않는다.
- 사용자와 연결된 외부 MCP 오류, 임의 파일/폴더, 개인 경로, 전투/제작 내용의
  보조 로그를 새로 읽지 않는다.
- `P1`은 **기록 양식 이상을 먼저 살피라는 순서**이지 실제 오류 심각도나 자동 코드 수정 우선순위가 아니다.
- AI 모델이 해당 주석을 받아 더 정확해졌는지는 **실험하지 않았으며 확인할 수 없다**.

## 하지 않는 것

새 패킷 수집, 복호화, CLI 명령, OCR·화면캡처, 입력, 사용자 PC 파일 수정,
백그라운드 에이전트 생성, Codex 추가 호출, 자동 코드 수정 승인, 깃허브 PR 병합,
운영 릴리스 배포, 실게임 수행. **기존 AI 코드 수정 기능 자체는 이미 존재하므로**
사용자가 기존 감시기를 켜면 그 기존 기능은 종전 안전 조건에서 동작한다.
23단계가 자동 수정을 비활성화시키거나 권한을 추가한다는 뜻은 아니다.

## 검증

`tests/ai-autopilot/test_incident_review_bridge_stage23.py`: 합성 오류 자료를 이용해
허용되는 로컬 오류 폴더만 연결, 기존 context-for와 과거 학습 근거는 불변,
Codex 프롬프트 안의 기존 신뢰 경계 보존, 권한 승인 불가, 임의 JSON 집계 위조 실패,
외부 MCP/심볼릭 링크/빈 데이터/기록 상한 초과 시 구형 프롬프트 유지,
결과 익명성, 최대 3개 항목 제한, 재수정 경로에 같은 정보 전달 여부를 확인한다.

Windows GitHub CI: `Read-only packet observation checks`,
`Abyss + Altering Scheduler Validation`, `Check V3 Production Engine`.
실게임 시험과 운영 배포는 별개이며 아직 수행하지 않는다.

작업 대상: PR #231 개발 브랜치. `main` 및 사용자의 현재 실행 버전은 변경하지 않는다.

## 후속

실제 오류 집계를 확보한 뒤, 사람이 검증한 **정답 레이블**이 있는 오류만 활용해
검토 우선순위가 분석에 도움이 되었는지를 A/B 실험으로 측정할 수 있다.
이는 실제 에러 감소나 완전 자동 수정의 근거가 되지 않는다.
