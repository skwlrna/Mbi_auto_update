# 음식 레시피 등록 (2026-11-10)

## 범위와 근거

`CraftingFoodRecipeCatalog`에 완성 음식 54종의 **1회 직접 투입 재료**를 등록했습니다.
`달걀 프라이`/`달걀프라이`, `토마토 리조토`/`토마토 리소토`는 명시적인 별칭입니다.
현재 `VerifiedFoodNames`의 56개 이름이 모두 54개 등록 레시피와 2개 별칭으로 연결됩니다.

52종은 외부 공개 자료를 확인·대조한 참고 레시피입니다. 추가 2종은 사용자가 제공한 1회 제작 상세창에서 전체 재료와 필요량을 직접 확인했습니다. 현재 CLI 원본으로 전체 레시피를 검증했다는 의미는 아닙니다.
`MissingIngredients`는 보유 중인 재료가 빠질 수 있으므로 전체 레시피로 사용하지 않았습니다.
생크림·마요네즈 같은 직접 투입 중간재를 우유·달걀 등 원재료로 치환하지 않습니다.
1회 생산량, 필요 시설, 요리 레벨은 이번 입력 재료 등록에서 추정하지 않았습니다.

## 코드 적용 범위

- 레시피 입력 목록, 출처 URL, 검토일과 1~10회 필요량 계산 API를 등록했습니다.
- 제작 화면의 기존 재료명 후보 목록에 등록 레시피의 재료명을 먼저 공급합니다. CLI의 1회 부족 목록이 비어 있어도 후보가 사라지지 않습니다.
- V3.3.08부터 등록 음식의 필요량·보유량·부족량·확보 완료를 레시피와 CLI로 판정합니다. 상세/퀘스트 재료명 OCR을 필수 조건에서 제거했습니다. 퀘스트 수량 OCR은 수급 클릭 행 위치를 찾는 데만 사용합니다.
- 가공 중간재의 기존 수급 정책은 수정하지 않습니다. 생강·셀러리 등 자동 수급 미지원 재료도 전체 레시피에는 포함됩니다.

## V3.3.08 수급 연결

CLI는 한 번의 최신 가방 스냅샷으로 전체 직접 입력 재료를 확인합니다. 충분한 구매 재료는 허용하고, 실제 부족한 수급 불가 재료만 기존 음식 건너뛰기 경로에 전달합니다. 중간재는 기존 재귀 가공기에 부족량만 전달합니다.
행을 클릭할 때는 수량과 CLI 재고로 후보를 대조합니다. 동일 수량의 복수 후보는 모두 채집 가능한 경우에만 허용하며, 어느 후보가 실제 확보되었는지 최신 재고로 확인한 뒤 전체 레시피를 다시 조회합니다. 화면 순서로 이름을 추정하지 않습니다.
행 위치 판독은 같은 팝업에서 세 번 재시도하며 실패하면 퀘스트 재생성 없이 정확한 위치 오류를 전달합니다. 기존 제작 완료/재고 확인 후 확정한 배치는 재실행하지 않습니다.

## V3.3.10 보관함 및 소량 배치

음식 재료는 가방·캐릭터 보관함·공용 보관함 합계로 판단합니다. 직접 재료와 알려진 하위 가공 재료 전체를 한 재고 응답에서 읽은 뒤, 10회부터 1회까지 자동 수급 불가 재료 부족을 검사하여 가능한 최대 배치를 선택합니다. 채집 가능한 원재료는 부족해도 수급 대상으로 남깁니다. 1회도 불가능할 때만 남은 목표를 건너뛰고 이미 확정한 제작 결과를 보존합니다.
새 제작 퀘스트는 생성 직후 클릭합니다. 음식 실행 요약은 일반 로그와 별도 보존하여 오류 업로드의 food-summary.log로 전달합니다.
