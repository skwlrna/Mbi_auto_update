# V3.2.88 — 통합 안정화 변경 제안

현재 공개 V3.2.87을 기준으로 **여러 안정화 작업을 한 번의 테스트/한 번의 새 버전**으로 묶습니다.

## 통합 범위

1. **제작 F10/프로세스 종료 후 중복 실행 차단 (#375)**:
   `CraftingRestartSafetyJournal`에 대상 품목·배치별 제작 직전 의도,
   재고 증가 확정 결과, 건너뛴/완료 품목을 기록합니다. 이전 실행의 미확정
   데이터가 있으면 확인창에서 기본값 '아니요'로 자동 재시작을 차단합니다.
   '예'를 명시적으로 누른 경우에도 자동 이어하기가 아니라,
   이전 기록을 보관한 뒤 사용자가 다시 선택한 **새 전체 목표**를 실행합니다.

2. **어비스 재입장 모집·로딩 장기 대기 알림**:
   같은 재입장 상태가 15분 지속되면 원인별로 한 번 로그에 알립니다.
   기존 무기한 대기, 취소, 실전 상황 검사, 입력 정책은 바꾸지 않습니다.
   기존 `AbyssClearEvidencePolicy`의 2프레임 클리어
   제목 + 터치 문구 증거 검증은 유지합니다.

3. **통합 모드 진단·Watchdog**:
   기존 PR #368의 입력 없는 진단 클래스와 Windows 읽기 전용
   프로세스 관찰 도구·모의 테스트를 가져옵니다. UI에 연결하는 것은
   **모드/로그 관찰 및 진단 경고만**이고, 기존 `StartSelected` 소유권,
   F9 시작, F10 중단, 매크로 재실행/클릭 루틴은 변경하지 않습니다.
   `SchedulerRunMonitor`는 OCR/재입장/반복 대기 알림 자체를
   진행 증거로 처리하지 않도록 보강합니다.

4. **다중가공 시설 진입**:
   현재의 고정 허브 2프레임·메뉴/팝업 차단·CLI 재확인과
   컴파일된 실화면 회귀 테스트를 유지합니다. 공개 이슈 #316의 원인별
   재클릭을 추측해 확대하지 않습니다. *실제 사용 환경의 최초 카드
   클릭 전후 영상/캡처가 없으면 이 문제의 확정 해결을 주장할 수 없습니다.*

## 제외

- 어비스 기믹 풀이 코드 변경
- 실게임 실행 및 외부 게임 명령 호출
- 근거 없는 재등록/재제작/재수령, 어비스 재입장·퇴장 클릭 추가
- 자동 코드 수정 및 게임 업데이트 강제 설치
- 이전 릴리스 덮어쓰기

## 오프라인 검증

- 제작 실제 `CraftingAutomation` 모의 엔진 + 파일 기반 중단/복원/동시 잠금.
- 어비스 클리어 제목-only 차단 정책, 재입장 15분 무입력 알림.
- 스케줄러 정체 경고의 반복 OCR 로그 무시.
- 제작·다중가공·입력·어비스 스케줄러 회귀 테스트.
- 통합 상태 감시 Linux/Windows 모의 검증과 UI 계약 빌드.

정식 배포는 이 통합 변경이 전체 CI 및 exact-main CI를
통과한 뒤 `V3.2.88` **한 번만** 발행하도록 별도
중복 태그/체크섬/롤백 파일 배포 게이트를 사용합니다.
실제 게임에서의 성공을 증명하지 않습니다.
