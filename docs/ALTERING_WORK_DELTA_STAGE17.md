# 17단계 — 가공 작업 제거·취소 가능성의 CLI 교차조회 진단

## 실사용 관측에 근거한 규칙

사용자가 동일한 PC와 같은 Stage 16 읽기 전용 CLI 테스트 창에서
옷감 작업 한 개를 수동으로 취소한 전후 두 번의 `CLI 1회 확인` 결과를 제공했다.

| CLI 집계 (작업 ID·종류 미확인) | 변경 전 | 변경 후 | 차이 |
|---|---:|---:|---:|
| 전체 가공 작업 행 | 32 | 31 | -1 |
| 진행 중 작업 행 | 3 | 2 | -1 |
| 완료 표시 행 | 25 | 25 | 0 |
| 그 외/대기 행 (차감 계산) | 4 | 4 | 0 |
| 인벤토리 항목 행 | 593 | 593 | 0 |
| 가공 레시피 행 | 91 | 91 | 0 |

**확인된 것:** 사용자가 그 사이에 옷감 가공을 취소했으며,
두 CLI 집계의 전체·진행 행이 1개씩 줄고 완료 표시 수는 유지되었다.

**확인되지 않은 것:** 특정 옷감 작업 ID/아이템 ID,
취소·회수·제거 중 실제 서버 이벤트 이름, 아이템 수령 여부, 소재 재고 변화,
그 사이의 다른 동시 작업 변동, 패킷 구조 또는 공식 이벤트 스키마.
집계 일치만으로 이를 확정하면 안 된다.

## 구현한 공통 진단 모델

`Telemetry/AlteringWorkDeltaDiagnostic.cs`

- 기존 `AlteringQueries.ParseWorks`를 통해 검증한 2회 조회 결과를
  **총 작업·진행 중·완료 표시·대기 작업 건수와 관측 시각**으로만 기억한다.
- 다음 수동 조회까지 새 작업 등록, 취소·제거 가능성, 완료 표시 증가,
  기타 변화, 무변화로 구분한다.
- `전체 감소 = 진행 감소`, `완료 표시 변화 없음`,
  `대기 변화 없음`일 때 `possible_work_removal_not_completion` 판정.
  이는 **취소 확정이 아니라 작업 제거·취소 가능성**이다.
- `전체 유지`, `진행 감소`, `완료 표시 같은 수 증가`이면
  `possible_progress_to_completed_receipt_unknown`.
  결과물 수령이나 배치 완료를 의미하지 않는다.
- 유효한 비교 간격은 최대 15분이며, 잘못된 응답·출처 거부·검증 실패는
  비교 기준을 버리고 다음 조회를 새로운 기준으로 사용한다.
- 작업별 이름·ID, 인벤토리 원문·캐릭터 정보·레시피·계정 정보는
  저장하지 않는다. 두 번의 조회 모두 서버 작업 행 집계의 비교일 뿐이다.
- 모든 결과는 `AuthorizesGameplay=false`,
  `CancellationProven=false`, `EvidenceOfReceipt=false`로 고정된다.

연결한 위치:
- 독립 실행형 Stage16 GUI: 사용자가 버튼을 눌렀을 때만 앞뒤 차이를 표시한다.
- 기존 모비매크로 `로그 / 진단`의 수동 상태 조회 창: 역시 버튼을 눌렀을 때만
  표시하며 자동화 실행 중에는 추가 CLI 조회를 하지 않는다.
- 옵트인 AI 감시기: **이미 완료된** `get_altering_works` 응답의 검증된
  집계만 참고하여 제한된 분류 `cli_altering_possible_removed_not_completed`,
  `cli_altering_possible_finished_receipt_unknown`를 최대 5초간 메모리에
  보관한다. 에러 이전의 증거만 `error.txt`에 추가한다. 추가 CLI 요청,
  패킷 파서, AI 명령 권한 부여, 재시도, 가공 등록은 하지 않는다.
- Stage15 오프라인 A/B 분석기에도 두 분류를 엄격한 허용 목록으로 추가했다.
  AI 진단이 개선됐다는 통계로 오해하지 않고 보조 단서 건수로만 집계한다.

## 자동 검증 및 기존 자동화 보호

`tests/common-observation/Stage17Tests.cs`는 다음을 합성 검증한다.
32→31/3→2/25→25 실측 건수, 정상 완료 **가능성** 패턴, 작업 추가,
여러 변화가 겹친 미확정 사례, 빈 목록, 시간 역전, 15분 만료,
원본 조회 실패·중단, AI 옵트인 비활성, 5초 증거 TTL,
감시기 재시작 시 캐시 삭제, 작업 ID/수령 오판 금지.

`tests/ai-autopilot/test_evidence_ab_stage15.py`는 새 분류를 기존 오류
문맥에서 정해진 힌트로만 인정하며, 임의의 `cancelled_confirmed`는
거부한다. GitHub Actions는 일반 Windows 빌드, 독립 테스트 ZIP,
어비스·다중가공·채집·제작·전리품·스케줄러 회귀 테스트를 실행한다.

**중요:** 개발 코드는 draft PR #231에만 있고 `main` 병합·운영 배포·
사용자 PC의 테스트 실행파일 자동 교체는 하지 않았다.
Stage17의 실제 PC 검증은 이후 새 테스트 ZIP에서 다시 두 번 조회해야 한다.
