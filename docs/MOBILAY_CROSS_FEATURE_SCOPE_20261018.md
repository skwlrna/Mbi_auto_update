# 모비레이 자료의 모비매크로 전체 기능 적용 범위 (2026-10-18)

> **범위 결정:** 어비스 특화 파서가 아니라 공통 **게임 관측 신호 계층**을 설계한다. 현재 데이터로 확인되지 않은 필드/패킷 ID/라이브 API는 정의하지 않는다. 운영 매크로는 변경하지 않는다.

## 근거와 분류

이번 사용자 제공 **비공개 파일 두 개**를 오프라인에서 확인했다. 원본 바이너리/개인 캐릭터 식별자/플레이어 목록은 GitHub에 올리지 않는다.

- `레이_DPS_20261018_173326.json`: `Version=4`, 기록 장소는 **알비 던전 2층 1구역**. 총 피해량, 경과 전투시간, 전투 이벤트 집계 824, 버프·스킬·몬스터별 집계, 초 단위 `CompactData.s` 67개, `UserRows`, `MapMembers`를 확인했다. **`Events` 배열은 비어 있으므로 824개의 원시 이벤트를 재생하는 형식이 아니다.** 스킬/버프 이름은 표기용 사전일 뿐 프로토콜 ID가 아니다.
- `Mobilay_CharacterInfo_20261018_173320_905_001.txt`: 1개 `IN` 방향 레코드와 **622,417바이트**의 16진수 페이로드(파일에 표기된 바이트 길이와 일치)를 확인했다. 텍스트 레코드의 숫자, 바이너리 오프셋 및 필드 의미는 검증되지 않았다. 이를 캐릭터 좌표, 스킬 패킷, 던전 문양 등으로 명명하거나 자동 디코딩하지 않는다.
- `main`의 기존 소스에서 `MabinogiMobileCli`는 `status`, `get_activity`, `get_current_environment`, `get_items`, `get_inventory`, `get_gatherable_items`, `get_alterable_items`, `get_altering_works`, `get_craftable_items`, `get_my_info`, `get_currencies`, `capabilities` 등 **읽기 전용 CLI 질의**를 명시적으로 제공한다. 이 목록은 '현재 모비레이 파일에 있는 데이터'를 뜻하지 않는다.
- `InventoryLootTracker`는 안정된 CLI 재조회 차분을 통해 보상을 확인한다. `ProductionStageMachine`은 생산 단계를 명시적으로 관리하며, `AutomationStartPreflightPolicy`는 게임 창과 UI 조건을 검사한다. 기존 확증 규칙을 모비레이 추정치로 대체해서는 안 된다.

## 아키텍처 — 기능별 파서를 복제하지 않는다

```text
모비레이 오프라인 내보내기 ----> 자료별 형식 검증 및 비식별화 ----┐
Windows 수신 메타데이터 -----> TCP 연결 / 시간대 근거 ------------┤
기존 읽기 전용 CLI -----------> 상태/재료/활동의 독립적인 근거 ---┼---> CommonObservation
화면 / OCR -------------------> 화면 기반 독립적인 근거 ----------┘      |
                                                                      +--> 오류/스케줄러 진단
                                                                      +--> 전투 통계 진단
                                                                      +--> 던전 공통 진단
                                                                      +--> 채집/가공/제작 차분 진단
```

모든 관측 항목은 `Source` (MobilayExport / NetworkMetadata / Cli / Screen),
`ObservedAt`, `DataKind`, `EvidenceLevel` (RawOpaque /
OfflineSummary / ValidatedReadOnly / ScreenVerified), `Freshness`,
`SourceVersion`, `ValidationError`를 보존한다. **없는 값은 unknown** 으로
남긴다. 주소, PID, 캐릭터 이름/ID, 바이너리 페이로드는 관측 결과/로그/PR에 싣지 않는다.
라이브 UI 업데이트 여부는 신선도/일치 여부를 근거로만 표시한다.
`CommonObservation`은 **자동화 조작 명령이 아닌 읽기 전용 진단 모델**이다.

우선순위:
1. **P0**: 두 형식의 오프라인 비식별 검사, 공통 관측 근거 모델, 스케줄러/AI 오류 진단 화면용 요약. 모비레이가 저장한 DPS 자료와 새 실시간 신호를 혼동하지 않는다.
2. **P1**: 일반 던전/어비스에서 전투 통계/화면 상태와 CLI 신호의 비일치 감시. 채집·가공·제작에는 기존 CLI 쿼리와 재료/수량 확인 실패 원인 진단을 공통 적용.
3. **P2**: 낚시, 기믹 위치, 이동, 보상 등 현재 파일에 없는 신호는 별도의 실제 동작 증거와 읽기 권한을 확인한 뒤에만 확장.

## 품질 게이트

- 원본 내보내기 및 캐릭터/파티 이름·계정 ID·IP·페이로드는 공개 PR 및 테스트 자료에 업로드하지 않는다. 로컬 오프라인 실측은 합성/비식별 fixture만 파생한다.
- 확인하지 않은 ID나 바이트 오프셋의 의미를 만들지 않는다. DPS 요약은 실시간 패킷 디코드와 동일시하지 않는다.
- 파일 크기/레코드 수/배열 길이/UTF-8·16진수 형식/수치 범위 검증 및 누락/잘림 오류를 테스트한다.
- 진단 신호는 UI 화면 증거, 권한 및 기존 CLI 안전 검증을 우회하지 않는다. 단일 출처의 관측량으로 자동 스킬·이동·보상 확정을 금지한다.
- `main` 병합 및 운영 자동화 입력 연결은 하지 않으며, 개발은 드래프트 PR에서만 한다.
