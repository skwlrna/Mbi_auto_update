# 25단계 — 11~24단계 통합·안전성 검증 및 26단계 준비 판정

## 목적과 범위

11~20단계의 읽기 전용 진단·화면 판정·AI 감시기 결합,
21단계의 기존 오류 근거 집계, 22단계의 고정 품질 검토 순위,
23단계의 기존 Codex 입력 내부 참고 주석, 24단계의 쌍 프롬프트 A/B
간의 관계를 합성 로그와 기존 소스 계약으로 통합 검사한다.

**25단계 통과 = 개발 브랜치에서 소스 계약과 오프라인 CI가 확인됨**을 의미한다.
실게임에서 오류가 줄었다거나, 수신 패킷 해석의 정확성이 증명되었다거나,
Codex가 실제 오류를 성공적으로 고쳤다는 뜻은 아니다.
26단계로 검토 후보가 될 수 있을 뿐, 병합·배포·자동 수리 승인으로 바뀌지 않는다.

## 새 검사기

- `source/FishingAutomation/ai-autopilot/integration_safety_gate_stage25.py`
- 인자 없이 실행: `python source/FishingAutomation/ai-autopilot/integration_safety_gate_stage25.py`
- GitHub Actions 체크아웃과 동일한 저장소 소스 파일 **9개만** 읽고,
  고정된 카테고리의 참/거짓 및 상태를 로컬 표준 출력 JSON으로 출력한다.
- 쓰기, Git 명령 실행, 게임 입력, 인터넷 연결, AI/Codex 실행, 사용자 로그 읽기 없음.
  읽을 수 없는 소스·심볼릭 링크·비정상 소스·스키마 변경은 검사 실패 처리.

### 10개 소스 계약

1. 일반 생산 빌드에 11~20단계의 passive 전처리기와 Python 진단 모듈이 포함됨
2. AI 감시기 명시적 실행 후에만 수신 자료 관측을 켜고 종료 시 끔
3. AI 오류 기록은 완료된 CLI·분류·화면 판정의 스냅샷만 읽음
4. 21~24단계가 크기/건수/경로 상한을 유지하고 검증된 스키마만 사용함
5. 비교 불가 근거를 실제 게임 충돌, 정답 검증, AI 정확도 상승으로 오인하지 않음
6. 새 검토 참고 정보는 기존 `<untrusted-log>` 범위만 사용함
7. Codex 격리 작업공간·소스 핀·등록 회귀 테스트·Draft PR·사람 검토 정책 유지
8. 기존 최신 오류 우선 큐를 새로운 검토 우선순위로 재정렬하지 않음
9. 24단계는 새 Codex 실행/파일 저장/게임 입력 없이 프롬프트 입력만 비교함
10. Windows CI에 14, 15, 21, 22, 23, 24, 25단계 테스트가 등록되어 있음

소스의 문자열/구조 검증은 실게임 행동의 의미 검증을 대신하지 않는다.
검사에 실패하면 `integration_contract_blocked`, 성공하면
`source_contracts_passed_review_required`이다.
`stage26_review_candidate=true`는 다음 검토 단계로 넘어갈 **후보** 표시일 뿐이다.

## 통합 시나리오

`tests/ai-autopilot/test_integration_safety_stage25.py`는
외부 자료나 패킷 없이 임시 로컬 폴더에 합성 오류를 작성한다.

- 채집: 활동 중 CLI+화면 검증, 의미상 호환 가능한 제한적 단서
- 가공: CLI+화면 두 근거가 존재하지만 의미 비교 불가
- 제작, 낚시, 어비스, 일반 던전, 페카 심층: 이미 확인된 화면 판정만
- 스케줄러: 해당 시점에 기록된 화면/CLI 단서가 없을 때의 격리 조건
- 주석 위조, 원본 오류 기록 손상, 모드 불일치, 정책 변경/상위 지시 경계 탈락
- 여러 기능에서 수집한 자료를 21→22→23→24로 순서대로 전달하여
  동일 입력 쌍의 허용된 차이만 발생하는지 검증

**25단계 추가 안전 개선:** 현재 오류의 CLI/분류/화면 주석이 손상됐거나
기록된 모드와 일치하지 않으면 23단계의 **전체 로그 집계 참고 주석을
해당 오류의 AI 분석 입력에 붙이지 않음**. 다른 정상 오류는 종전처럼
익명 집계에 대한 검토 참고를 얻을 수 있다. 원본 로그는 여전히
기존 `<untrusted-log>` 경계 안에서만 사용한다.
이 검증을 위한 진단 도구 실행은 Codex 수정 권한을 추가하지 않는다.

## 배포 전 판정

25단계는 아래 사항을 **확정하지 않는다**:

- 실제 사용자 PC 오류 기록을 분석했는지
- 수신 패킷에서 게임 상태가 제대로 확인되는지
- 화면 자동화와 결합했을 때 실게임 입력이 완전히 안전한지
- 실제 AI 분석 및 수정이 정답인지
- 사용자의 승인과 롤백 방법이 운영 환경에서 확보됐는지
- 병합 대상 `main`과 배포 아티팩트가 일치하는지

26단계에서는 GitHub 개발 PR의 **최종 SHA에 대한** 모든 CI를 확인하고,
출시/롤백 체크리스트와 실사용 테스트 절차를 정리해야 한다.
운영 배포, `main` 병합 및 사용자 PC 시험은 별도 확인·승인 없이
완료됐다고 주장하지 않는다.

GitHub 작업은 PR #231의 **draft** 개발 브랜치에서만 한다.
