모비매크로 패킷 수신 진단 도구 (개발용)

[목적]
게임 상태 분석이나 자동화 연결이 아닌, 특정 TCP 수신 포트의 프레임 개수만 확인하는 진단 도구입니다.
모비레이의 공개 API나 게임 패킷 ID를 확인한 프로그램이 아닙니다.

[사용 전 확인]
- Windows 10/11 x64 컴퓨터와 Npcap 호환 캡처 드라이버가 필요합니다.
- 네트워크 수동 캡처가 게임 정책 및 사용 환경에서 허용되는 경우에만 사용하세요.
- 실행 파일이 포함된 ZIP 전체를 압축 해제하세요. 운영 중인 모비매크로 폴더에 덮어쓰지 마세요.

[실행: 복잡한 명령어 불필요]
1) 압축을 해제한 폴더에서 RunReceiveProbe.cmd 를 더블클릭하세요.
2) 네트워크 어댑터 목록이 표시됩니다. 사용 중인 연결(예: Realtek 유선)을 확인하고 번호를 입력하세요.
3) 진단 시간을 1~30초 중에서 선택하세요. 보통 10초면 됩니다.
4) 실제 캡처를 허용하려면 정확히 YES 를 입력하세요. 취소하려면 빈칸/다른 문자를 입력하세요.
5) 실행 중 1초마다 read_only_probe_window 줄이 표시됩니다.
   frames=0 이 잠깐 나와도 게임 연결 종료를 뜻하지 않습니다.
6) 시작 전과 종료 후 read_only_tcp_owner_before / read_only_tcp_owner_after도 표시됩니다.
   owner_names는 Windows TCP 연결 테이블의 원격 포트 16000 사용 프로세스 이름만
   표시한 것입니다. 프로세스 이름으로 실제 프레임 주인이나 게임 상태가 증명되지는 않습니다.
   IPv4 연결만 확인하며 IPv6 연결은 조사하지 않습니다.
7) 정해진 시간 뒤 기존 read_only_probe_result 합계와
   read_only_probe_activity 요약이 표시됩니다.
8) matched_frames, frame_bytes, status, active_windows, trailing_quiet_windows,
   longest_quiet_windows, activity 값만 알려주면 됩니다.
   원격 포트 소유 프로세스는 궁금한 경우 이름만 확인하고 알려줘도 됩니다.
   민감해 보이는 프로세스 이름은 가려서 공유하세요.
   IP 주소, 계정, 원본 패킷 데이터, 장치 식별자, 전체 화면을 공유할 필요가 없습니다.

[해석]
matched_frames > 0: 선택한 어댑터에서 TCP 출발지 포트 16000인 수신 프레임이 감지됨
matched_frames = 0: 해당 어댑터/조건에서는 감지되지 않음
어느 쪽도 게임 소유 패킷인지, 패킷의 의미가 무엇인지는 증명하지 않습니다.
실제 모비레이/게임 연결 기능이나 매크로 입력 제어는 구현되지 않았습니다.

[안전/개인정보]
- 프로그램은 원시 패킷, PCAP, IP, 캐릭터 이름, 인증 토큰을 디스크나 GitHub에 저장하지 않습니다.
- 네트워크 패킷을 전송·변조하지 않으며, 키보드/마우스 입력을 실행하지 않습니다.
- 승인 문구 YES 없이 수신 캡처는 시작되지 않습니다. 시간 상한은 30초입니다.
- 창을 닫거나 Ctrl+C 를 누르면 종료됩니다.
- 주 프로그램 설치 파일과 분리된 진단 빌드이며 운영 모비매크로는 변경되지 않습니다.
- Windows가 서명되지 않은 실행 파일을 차단하거나 경고하면 무조건 우회하지 말고 출처와 해시를 먼저 확인하세요.

[추천: 앞으로는 한 번에 테스트]
기존 RunReceiveProbe.cmd는 단일 10초 진단용입니다.
새 RunAllChecks.cmd를 더블클릭하면 3가지 조건을 한 번에 확인할 수 있습니다.
각 구간의 캡처는 10초이며, 총 캡처 시간은 최대 30초입니다.
1) 게임 클라이언트 완전히 종료(캐릭터 선택 화면이 아닌 게임 자체 종료)
2) RunAllChecks.cmd 실행 → Realtek 네트워크 장치 번호 선택(이전에 3번)
3) 한 번만 대문자 YES 입력: 캡처와 읽기 전용 CLI(status / get_activity) 응답 상태 비교에 동의
4) 안내에 맞춰 게임이 종료된 상태에서 대문자 READY 입력 → 10초 검사
5) 캐릭터 게임 접속 후 가만히 있는 상태에서 READY → 10초 검사
6) 게임에 접속한 채 READY 입력 후 10초 안에 직접 캐릭터를 조금 움직여 봅니다.
   프로그램은 게임을 대신 조작하지 않습니다.
7) ALL_STAGES_COMPLETE 문구가 나오면 맨 아래 3-STAGE FINAL COMPARISON 항목의
   compare stage= 로 시작하는 3줄만 한 장의 스크린샷으로 보내 주세요.
   로그 파일을 저장하지 않고, 확인을 위한 결과 요약만 화면에 표시합니다.

[세 구간의 의미]
client_closed: 게임 자체 종료 상태 비교 기준
character_connected_idle: 접속 상태지만 움직이지 않고 대기
character_connected_activity: 본인이 직접 움직인 상태
두 개의 추가 CLI 명령은 status/get_activity 조회만 실행합니다.
CLI 자체가 없거나 제한된 경우 cli_not_installed, cli_unavailable, cli_timeout 같은 상태만 나옵니다.
CLI 응답 본문, 계정/캐릭터 식별정보, 토큰은 화면에 출력하지 않습니다.
TCP 연결 소유 프로세스 이름이나 포트 16000 수신량은 게임 패킷 의미를 증명하지 않습니다.

[취소/참고]
각 구간마다 READY 외의 값을 입력하면 남은 테스트는 실행되지 않습니다.
처음 동의할 때 YES가 아닌 값을 입력해도 캡처와 CLI 조회는 시작되지 않습니다.
전체 절차에서 게임 종료·접속·활동은 사용자가 직접 해야 합니다.
컴퓨터에 설치된 모비매크로 및 모비레이를 수정하지 않습니다.


[새 버전: 실제 TCP 연결 대조 / CLI 응답 수정]
이번 통합 진단의 마지막 compare stage= 세 줄에는 추가로 다음 항목이 표시됩니다.
- flow_matched: 수신 TCP 프레임과 Windows TCP 연결의 원격/로컬 IP·포트 조합이 일치한 수
- named_candidate_frames: 이 중 Windows 프로세스 이름이 MabinogiMobile인 연결과 일치한 수
- flow_unmatched: IPv4 TCP 헤더는 읽혔지만 연결 스냅샷에는 나타나지 않은 프레임 수
- flow_status: 연결 테이블의 유무 및 주소/포트 일치 상태
개인 IP 주소나 실제 포트 번호(기준 원격 포트 16000 제외)는 화면이나 파일에 기록하지 않습니다.
단, 내부 RAM에서는 비교에 필요한 TCP 네트워크 헤더 정보만 일시적으로 사용합니다.
이 대조는 OS 연결 스냅샷을 각 검사 구간의 시작/종료에 가져오기 때문에
짧은 연결 변화는 포착하지 못할 수 있습니다. 게임 데이터 내용은 해석하지 않습니다.

CLI는 기존 모비매크로 코드의 규칙대로 status 명령에서 body.pipe=connected 를,
get_activity 명령에서 정상 JSON 객체 형태를 확인하도록 수정됐습니다.
예전 cli_json_without_status 결과는 진단기의 최상위 status 필드 가정 문제였으며
게임이 끊겼다는 의미가 아니었습니다. 새로운 응답 검사도 진단 상태로만 사용합니다.

이 버전 역시 RunAllChecks.cmd 한 번으로 세 단계 통합 검사를 수행합니다.
마지막 compare stage= 3줄만 전달하면 됩니다.
