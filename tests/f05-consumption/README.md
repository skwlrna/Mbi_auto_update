# F05 — 영속적 다중가공 소비 장부 (Critical)

기준 main: `37018a35b950669a7446e4d509e86d3189197a2a` (N02 #114 병합 포함).
범위: F05 소비/등록 경계의 거래 영속화와 이중 보정 방지. N02/N03, 게임 UI, 딜레이, 좌표, 출시 버전은 변경하지 않는다.

## 기존 결함

기존 `MultiAlteringConsumptionLedger`는 등록 직전 CLI 보유량을 메모리에만 유지했다.
확인된 등록 직후 생산자의 `CreditedInternalConsumptionQuantity`에 차이를 쓰고,
그 다음에야 소비자 `QueuedWorks`를 확정했다. 충돌/취소/크래시 위치에 따라
**동일 감소분을 다른 등록에 잘못 귀속하거나 다시 보정**할 여지가 있었다.
재귀 중간재료 등록도 동일한 휘발성 관측기를 사용했다.

## 수정 불변식

- **Prepared**: 게임 등록 입력 전, 배치의 `batch.json`에 소비자 고유 키, 거래 ID,
  생산자별 before-image를 원자 저장한다. 이 단계가 실패하면 게임 입력은 시작하지 않는다.
- **Applied**: CLI가 등록을 확인한 후 after-image를 읽어 차이를 계산한다.
  **생산자 여러 개의 소비 보정 + 거래 ID 적용 기록 + Prepared 제거**를 단일
  manifest 원자 교체로 저장한다. 적용된 동일 ID를 다시 호출하면 무조건 no-op.
- 등록 후 크래시·F10 시 Prepared가 남으면 재시작에서 **RecoveryRequired**로 안전
  중지하며 소비/등록 재시도는 하지 않는다. Applied가 남고 소비자 `PendingRegistration`
  이 확정되지 않았다면 메인·재귀 소비자 모두 자동 재개 차단.
- producer 메모리 콜백은 **재조회만 수행**하며 가산하지 않는다. 오래된 stage/session
  snapshot이 보정값을 줄이지 않도록 `SaveItem`에서 이전 영구 보정액을 유지한다.
- 이미 실행 중인 v1 N02 배치에는 해당 거래 증거가 없다. 무등록/수량 불변/대기열
  비었음을 증명한 경우에만 v2 manifest로 이관; 나머지는 안전 정지한다.
  버전은 파일 스키마 버전이며 애플리케이션 버전을 변경하지 않는다.
- 직렬화 임시 파일 + Flush(true) + 원자 교체를 기존 N02 저장 절차와 공유한다.
  F10 콜백은 저장이나 락을 기다리지 않는다.

## 결정적 테스트

`tests/f05-consumption`에서 실제 BatchStore와 실제 Ledger를 묶어 임시 디렉터리를
사용한다. fake CLI 보유량으로 검사하며 게임/드라이버 입력 없음.

1. 등록 전 Prepared 영구 저장 및 등록 후 Applied 원자 저장
2. 동일 거래 ID 중복 적용 방지
3. 생산자 2개 동시 소비 원자 반영
4. 오래된 메모리 세션 저장 시 영구 크레딧 보존
5. Prepared 크래시 후 재시작 차단
6. 등록 후 원자 교체 실패의 준비 기록 보존과 재시작 차단
7. 미해결 거래에서 새 준비·수령 차단
8. 정상 완료 거래 재시작 후 크레딧 유지
9. 메인 소비자 등록 확정 전 중단 → 차단
10. 재귀 중간재료 소비자 등록 확정 전 중단 → 차단
11. 거래 기록 없는 v1 진행 배치 자동 이관 차단
12. v1 무등록/기준 수량 불변 배치만 원자 이관
13. 취소된 캡처에서 등록/준비 기록 없음

Windows CI에서 기존 N02(44), N03(58), L2 및 나머지 회귀 검사를 모두 유지한다.

## 한계와 운영 정책

- Prepared를 쓴 뒤 게임 입력 전에 취소됐더라도 기록만으로 입력이 없었다고
  증명할 수 없으므로 자동 재개하지 않는다. 안전 정지 상태는 별도 검토 필요.
- CLI 재료 보유량 변화만으로 외부 수동 소비를 완벽히 구분할 수 없다. 외부 조작,
  실제 게임 입력/수령, 설치된 Interception 및 OS 강제 종료는 실게임 검증 미완료.
- 네이티브 디스크/전원 손실에서 Flush/rename 완전 내구성은 하드웨어 전제.
- main 병합 및 Release는 이 PR에서 수행하지 않는다.
